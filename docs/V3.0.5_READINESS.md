# 分层就绪与发布检查

仍复用 HealthCheckRegistry、HealthCheckRun、HealthIncident 和 RecoveryAction，不创建平行监控数据库。仪表盘读已存探针结果，不在每次页面加载时触发外部探测。

- 基础设施层包括数据库、迁移、Redis、Broker/Worker 和实际阅读文件。
- 应用层增加真实工作台只读构造、活动公开指针和公开 serializer。后台处理故障不能代替书目编辑状态，语义故障呈降级。
- 公网层单独检查已配置 HTTPS 入口的 API 就绪 JSON，不能只认 HTTP 200。外部失败只提供重新探测，不授权自动回退应用。

`/api/ready/` 仍兼容旧部署启动检查，但明确声明只验证 database/schema。它不代表工作台、Reader、公网或完整站点正常。

`python manage.py check_functional_readiness` 执行只读源码功能 smoke，不创建馆藏，不写探针记录，也不自动恢复。无真实工作台或 PDF 样本时返回 SKIPPED 并失败，避免空数据库通过 release gate。`--external` 只增加公网 API 检查。命令输出明确 `full_release_acceptance=false`，它不能替代真实登录、PDF Range、公开 Work/Reader 页面、搜索、权限 E2E 或恢复演练。

两个探针周期之外的历史结果在层摘要标为 unknown。显示层只区分来源与新鲜度，不把旧健康记录当成当前线上事实。

本轮相关后端 34 项、空样本门槛 1 项通过。公网 200 但正文不是有效就绪 JSON 的场景另有专项。TypeScript、lint、build 与 181 项 Node 回归通过。生产探针与完整公网验收尚未执行。
