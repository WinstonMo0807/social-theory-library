# 3.0.8.2 后端性能与存储治理

2026-09-29。应用基线14a41a1。独立工作区开发，观点精度实验/分析按用户要求搁置，未混入本版。当前已完成实现和下述验证，准备推送；尚未生产切换，无既有NAS文件删除。

## 原审计逐项处理

| 原问题 | 本版结果 | 保留的边界 |
| --- | --- | --- |
| 队列反复编译/执行状态查询 | 请求内物化CTE计算状态后复用计数、预览及当前页 | 不持久化第二套业务状态；总数、权限、分页与预览默认优先级顺序保持 |
| 每本预取整段任务历史 | 按版本、任务类型、文件及正文修订分组，保留最新创建任务及10条最近更新记录 | 保留当前失败解析及能力诊断；全历史仍在处理中心，列表提供总数/截断标记 |
| 检索结果反复读取和散列 | 不读取水合过程不用的normalized_text；同一次请求每原文单元只计算一次散列 | 仍逐项核对原文切片、权限和当前修订；400候选完整复核及精确可见计数未改 |
| 逐段索引提交与等待 | 每原文单元内最多8段一批写Meilisearch | embedding仍逐段、模型/向量/ID不变；外部成功后才ready；时间片到期提前提交已准备部分并断点续做 |
| 重叠去重平方比较 | 按文件/页码分桶后比较 | 保留原候选顺序、精确去重与80%重叠规则；同页最坏仍可能平方增长 |
| OCR重复页面扫描 | 一页提交成功后复用该次剩余计划，避免立刻再读整本页面状态 | 下一任务仍完整复核来源/检查点；单页保存、暂停/恢复/任务身份校验保留 |
| 深树逐层查询 | 本版未改 | 真实深度和频率不足以支持引入闭包表/新树结构 |
| 推理换载/串行锁 | 本版未改 | 不扩大模型、不减少精度、不取消保护锁 |
| 每轮打包复制大量依赖 | 准确Git提交源码打包器、备份原件直接入归档、只读存储审计命令 | 历史包/原件/模型不自动删除，具体清理候选单列 |

没有换技术栈、没有migration、没有改数据库权限或活动索引。不是全部原审计项都已解决：全候选分页复核、全馆scope枚举上限、其他关联历史和大规模状态表达式仍有后续优化空间。

## 存储与发布

NAS约35GB对应`/volume2/library/docker`37.72GB / 35.13GiB，其中旧library-upload 17.74GB、当前应用19.96GB。当前应用内backup/rollback约15.15GB。详细可清理范围、不能直接删除的资料及原因见[NAS存储审计](NAS_STORAGE_AUDIT_2026-09-29.md)。

新增命令：

```powershell
python manage.py audit_library_storage --max-entries 100000
python scripts/package_release_source.py --ref <已提交SHA> --output <新的源码归档路径.tar.gz>
```

审计命令只读配置中的原件、阅读、上传、备份目录，不解析凭据或删除文件。打包器仅归档已提交的Git对象，拒绝覆盖已有归档；它是源码发布物，不代替灾难恢复备份或实际运行镜像。

本版API/Web版本统一3.0.8.2，OpenAPI版本从同一APP_VERSION读取。Git推送不等于NAS已升级；生产切换仍需当前授权范围、新鲜备份/回退、镜像及公网受影响功能核验。保留全部3.0.8.1镜像与数据恢复入口，后续无需破坏性迁移。
