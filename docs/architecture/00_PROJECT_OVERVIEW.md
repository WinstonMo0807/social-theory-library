# 00 · 项目概览

[架构目录](README.md) · [系统架构 →](01_SYSTEM_ARCHITECTURE.md)

Social Theory Library（社会理论书库，STL）围绕社会学、人类学、民族学组织文献、人物、理论、主题和公开策展。它既是版本明确的文献目录，也是从研究问题返回原文的阅读环境。学科定位不意味着删除其他社会科学馆藏。

## 三类工作空间

| 空间 | 目的与实际入口 | 数据边界 |
| --- | --- | --- |
| 公开网站 | `/` 欢迎；`/home` 首页；学者、理论流派、主题、学科/子学科、知识地图、阅读路径、特别策划、书目详情 | 读取已生效公开修订；公开书目不代表 PDF 向匿名用户开放 |
| 登录读者 | `/explore` 书目/原文/观点检索；`/reader/[assetId]` 阅读；`/account` 进度、笔记、收藏、书单、计划、研究、引文核对、分享 | 原文与下载须登录；私人正文、研究内容按本人及明确分享范围访问 |
| 管理工作区 | `/admin` 上传、编目、馆藏、处理、知识对象、媒体、编排、策划、发布、用户和运行维护 | capability 授权；编辑保存、人工确认、正式发布、派生投影各有记录 |

入口依据：[web/app](../../web/app)、[AdminShell](../../web/components/admin-shell.tsx)、[权限类](../../api/common/permissions.py)。2026-11-09 匿名访问 Explore、Reader 和账户页实际进入登录；已授权会话可进入管理工作区及读者中心。

## 从发现到原文

书目搜索回答“有哪些文献”；全文/原文搜索定位段落；观点检索以问题寻找有出处的相关论述。当前 `DiscoverySearchSession` 将异步结果的身份与排序保存下来，每次读取仍重新核验来源权限和发布状态，不保存第二份可永久公开的引文库。深检索、语义重排与常规关键词不是相同的可用性指标。

PDF Reader 使用 PDF.js，结合清单、页码映射、目录、页内文本定位和 Range 文件访问。物理 PDF 页、印刷页码、正文修订与文本偏移分别记录。人工改字、重新 OCR、重新生成目录不应被理解为改写原始 PDF。

书库问答和私人连续研究复用馆藏与检索。私人研究可使用馆长配置的 Provider，STL 助手有独立模型选择；“本地推理存在”不能推导所有 AI 请求都不出站。实际可用性取决于已启用能力、模型与 Provider，见 [运行架构](02_RUNTIME_ARCHITECTURE.md)和[权限](11_PERMISSIONS_AND_SECURITY.md)。

## 知识组织不是单一分类树

一部作品可以同时研究多个主题、使用某种理论、批评另一传统，由不同责任者完成某些章节，并进入多个公共阅读路径。当前系统用 `Work`、`Edition`、责任者、知识节点、关系和证据分别表达这些含义。人物规范记录不等于可公开的学者档案，主题不等于学科，理论关联也不等于思想归属。

公开策展包括推荐期/文章、项目组织、原文证据模块和页面编排。`CurationProject` 管理协作与选材；`RecommendationIssue` 管理可发布文章；`EditorialRevision` 保存审核与公开修订。页面版位也使用 `EditorialRevision` 的 `content_placement` 类型及命令回执，没有独立的 `ContentPlacement` 数据模型。不能将“项目保存”理解成整本书知识自动完成或文章已经公开。

## 当前状态与范围

API、Web 源码版本为 4.0.0；公网运行的是 2026-11-09 的 curation-publish-r1。旧 main 为 3.0.9.1，本轮按运行文件补齐源码后形成新的 Git 基线。[审计版本](AUDIT_BASELINE.md)明确了证明强度：源文件相符，不能倒推生产原先由本轮新提交构建。

当前提供完整应用源码与维护文档；根目录未发现项目级 LICENSE，也没有 `.github/workflows` CI。不能宣称已取得 OSI 开源许可、CI 全绿或性能保证。第三方许可证与项目整体授权是不同事项。
