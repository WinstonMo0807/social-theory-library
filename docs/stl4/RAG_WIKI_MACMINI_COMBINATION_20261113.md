# 社科长书 RAG、持续 Wiki 与 Mac mini 运行方案

日期：2026-11-13。本文是当前实现、研究取舍与待实施工作的对应记录，不是整书分析完成证明。

## 已确定的部署边界

用户确定大部分服务迁到 Mac mini，NAS 主要承担存储。目标为 Mac mini 运行 Web、Django API、PostgreSQL、Redis/Celery、Meilisearch、解析与模型计算；NAS 保存原件、馆藏文件、派生文件和备份。迁移期间只有一个正式写入端，候选库只用于验证。正式数据、公网、DNS、隧道切换仍需最后授权；Intelligence 独立工作台不恢复，MCP 本轮不改动。

PostgreSQL、Redis 持久化、Meilisearch 活动索引、模型缓存及计算临时文件放在 Mac mini 本地磁盘。NAS 文件挂载仍沿现有资产相对路径，不改变 Work/Edition/Asset 身份。上传和派生结果必须检查 NAS 挂载真实可用，挂载断开不能把同名本地空目录当作馆藏目录。网络文件系统不是本轮数据库或活动索引的默认位置。

容器承载业务服务；需要 Apple GPU 的模型在 macOS 原生执行环境按实际支持情况使用 MPS，沿现有 Provider/远程执行协议调用。不能把 Linux ARM 镜像可启动等同于能够使用 Apple GPU。[PyTorch MPS 文档](https://docs.pytorch.org/docs/2.15/notes/mps.html)与[Docker Mac 安装文档](https://docs.docker.com/desktop/setup/install/mac-install/)分别说明运行环境；所购机型、内存、磁盘和对应依赖安装尚未实测，因此不预设模型尺寸或吞吐。

## 选择的组合

组合主干是**原文混合检索 + 真实文献层级 + 按序论证记录 + 来源独立的陈述关联 + 依赖驱动的 Wiki 修订**。全库检索负责找材料，长书读取负责建立连续理解，Wiki 保存经过审核的解释。三者共用来源、权限和版本，职责不互相替代。

| 环节 | 当前采用及复用 | 针对 STL 的限制或修改 | 状态 |
|---|---|---|---|
| 正文身份与定位 | PostgreSQL 不可变正文快照、DocumentNode、EvidenceAnchor/Segment；既有 PDF 阅读器 | 固定译本/资产/正文修订；Unicode code point 区间；跨页多片段；无可信几何不造坐标 | 代码及指定真实引用已验证 |
| 结构解析 | 原 Page/TextBlock/OCR/人工目录优先，按需 Docling | 只补质量不足范围；标题需原文回查；脚注不无条件拼入正文；人工结构保留 | 指定范围已验证，三书全部图表和空页尚未核验 |
| 原文召回 | Meilisearch 关键词、现有多语向量通道、RRF、重排、去重与文献多样性 | 精确引文走原文通道；关键词不等待模型；公开来源在召回与输出时均核对 | 关键词实测；本候选向量为 0，未证明混合模型质量 |
| 上下文增强 | 借用 Contextual Retrieval 的片段语境思想 | 目前只使用可信书名、章节路径与材料类型，单独存 context_text；不把生成上下文伪装成引文或主张者 | 已接同一真实消费者；不是论文中 LLM 上下文 + BM25 的完整复现 |
| 长书理解 | 固定 DocETL map 适配、STL 严格结构化调用、顺序 fold、独立窗口产物 | 全范围读取账本；保留逐窗论点、反例和适用条件；正文回查；不抽样代替整书 | 代理模式已完成 76 页章节；三部整书未完成 |
| 跨书关联 | Entity 规范身份、Assertion/参与者/来源/立场 | 同名不等同；批评、使用、引用、继承不混用；相反解释和不同译本可并存 | 正式来源模型已有；有界图排序仍待实现和比较 |
| 持续 Wiki | 借用 LLM Wiki 的持续编纂与交叉引用模式；复用订阅、依赖、稳定区块、ChangeSet、EditorialRevision | 数据库唯一权威；机器提出局部 patch；管理员审核；人工正文受保护；私人研究不默认进入全馆 | 按章节草稿与回滚应用已验证；自动整书 Provider 路径未验证 |

### 为什么不整包安装所有 RAG 项目

- [Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)直接对应小片段失去语境的问题。STL 已采用来源语境增强，但 Meilisearch 现有排序不是 BM25，不能套用该文章报告的效果数字。
- [RAPTOR](https://arxiv.org/html/2401.18059v1)用 UMAP/GMM 软聚类与递归摘要构建多层检索树。它适合跨段主题聚合，但聚类不保证作者论证顺序。STL 先使用真实部、章、节层级；生成摘要仅作为寻找原文的派生入口。没有把章节树命名为 RAPTOR 已实现。
- [PageIndex](https://github.com/VectifyAI/PageIndex)强调文档树和推理定位，可用于已选长书内深入阅读。全库仍保留段落召回，避免第一层选错书造成永久漏检；其 cloud-only 的 FileSystem 能力不能当作本地百万馆藏能力。
- [GraphRAG](https://microsoft.github.io/graphrag/query/overview/)的局部、全局与 DRIFT 查询针对不同问题；全局社区报告 map-reduce 有明显计算成本。STL 不把机器社区认定为理论流派，不把全馆社区重算放进每次入库流程。
- [LightRAG](https://github.com/HKUDS/LightRAG)具有图/文本检索及增量、删除恢复能力。查阅其 [operate.py](https://github.com/HKUDS/LightRAG/blob/main/lightrag/operate.py) 可见实体与边的聚合入口；STL 必须以规范 ID 和来源独立 Assertion 作为前置约束，不能直接让名称聚合接管已有知识身份。此次未复制上游代码或安装其业务存储。
- [HippoRAG 2](https://arxiv.org/html/2502.14802v2)把段落、短语、事实检索与 Personalized PageRank 结合。当前[官方实现](https://github.com/OSU-NLP-Group/HippoRAG/blob/main/src/hipporag/HippoRAG.py)对图的无向投影执行 PPR，并存在对事实/段落向量数组打分的路径。STL 只把它作为限定候选图上的比较算法；相关性传播不证明影响、认同或因果方向。上述 main 链接是本次查阅入口，不是已锁定部署依赖。
- [STORM](https://aclanthology.org/2024.naacl-long.347/)的多视角提问和提纲组织适用于主题、特别策划的证据收集。STL 不需要另建模拟人物代理系统；问题与反方材料可以进入同一受限检索和编纂过程。
- [Late Chunking](https://arxiv.org/abs/2409.04701)是在 transformer 编码后、池化前切块，不等于普通 embeddings API 分批上传。只有所选模型暴露相应能力、经过中文与译本样本验证后才启用；目前未启用。

LLM Wiki 本身是[持续知识编纂模式说明](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)，不是统一的标准算法包。STL 采用其积累知识、维护交叉引用和记录矛盾的思想，正式正文与审核仍由现有数据库管理。

## STL 特化算法的具体契约

以下“特化”指现有方法的领域适配，不声称原创论文算法或已取得新的 benchmark 成绩。

### 1. 原文与语境双通道

已实现：同一片段保存原文及其可信层级语境。原文召回、向量召回和语境召回统一 RRF：`sum(weight / (60 + rank))`，当前权重分别为 1、1、0.6；这些是候选初值，未经调参证明最优。精确引文与限定文本域关闭语境分支。原文定位始终回查固定修订，不从 context_text 计算偏移。

待完善：并行保留全库段落召回和作品/章节路由，路由作为额外候选来源，不作为全库检索的唯一入口。概念相关不能冒充作者认同；用户问“批评”时不能只因共现而排入“批评者”。

### 2. OCR 小单元与阅读大上下文分离

已实现：模型输入可合并同页、同类型、仅隔原始空白的短行，覆盖账本仍保留原节点。引用继续返回原始字符范围，脚注按明确引用关联扩展。

待完善：当前索引仍逐叶节点切片，治理一书 12,267 个结构节点、规训一书 10,269 个，存在明显短行放大。下一步在可恢复的派生索引中验证有来源的段落/窗口聚合，必须同步修改范围验证、locator 和投影版本；不能为了减少索引量把跨段/跨页关系写成未经验证的正文结构。候选旧有效索引在新代际完成前保留。

### 3. 长书按序分析与可恢复论证记录

已实现：范围清单 → 逐窗分析 → 按真实顺序 fold → 身份候选 → 来源陈述 → 区块 patch。窗口记录哈希、解析版本、模型身份与原文范围；无候选也是成功产物。严格入口拒绝静默截断。DocETL 目前实际使用固定版本 map，经薄适配调用 STL transport；顺序 fold 和有界身份比较由 STL 编排，不能称已使用 DocETL 默认 resolve/reduce 全管线。[DocETL reduce](https://ucbepic.github.io/docetl/operators/reduce/) 默认 associative 语义不直接适用于作者论证顺序。

本轮修复：完整节点清单只保留在阶段一来源产物中，频繁更新的进度字段只引用产物ID及哈希；旧run恢复时一次压缩，完整清单与已完成计数都保留。同一不可变结构与范围恢复不再改写清单；覆盖指纹包含prompt/schema、实际模型配置、结构与范围，改变时重新核算。逐窗原产物保持，综合不能取代原产物。恢复仍会读取完整所选结构并遍历缓存，尚未消除全部恢复开销。

待验证：三本整书的全部可读正文、长章中断、遗漏与反例记录，以及前面章节修改后顺序综合后缀的正确失效。后缀重算具有顺序依赖，不应误报为“只重算一个窗口”。

### 4. 有来源、角色受限的跨书图检索

选定设计，尚未接入线上：图为查询投影，节点采用规范 Entity、Assertion 和 EvidenceAnchor；陈述保留主张者、来源、谓词、方向、表达身份、时间/地区/对象/概念用法与证据立场。先由混合检索取有界种子，再扩展指定谓词和来源范围；最多两跳，明确候选与计算预算。以限定图 PPR 与不使用图的基线比较，输出路径和原文，不输出“图相邻所以有影响”的判断。

一条“作者批评被引述学者的观点”保留两种归属，不能从书籍责任者推定全部主张者；共现只用于候选定位。支持与反对的材料分别保留，不用次数投票决定争论。预算和默认开关须由三书及后续馆藏样本决定，未达到效果门槛则保留原文检索路径。

### 5. 持续 Wiki 的依赖与冲突

已实现的依赖单位包括正文修订、章节产物、实体与页面区块。新增证据提出增加、替换、删除建议，保留基准哈希、理由与引用。修改头像或排版不会要求重做全文 OCR。已拒绝的同源同内容建议保留拒绝决定；改了证据或实质内容才形成新候选。

本轮修复：人工正文保护覆盖 wiki_agent、wiki_compilation 等所有非人工草稿来源；外部产物提交的 human_edited 不能自行成为人工审核事实。管理员在原审核入口实际修改区块后，才形成受保护的人工编辑状态。没有修改 MCP transport 或其公网部署。

## 自动维护与迁移顺序

| 变化 | 必须即时处理 | 可排队的计算 |
|---|---|---|
| 撤回、权限改变 | API/阅读器/检索结果再次校验并拒绝无权来源 | 派生索引清理、受影响知识区块更新 |
| 新文献/正文修订 | 保存文件与不可变来源，返回真实就绪状态 | 当前来源结构、关键词、向量、已订阅编纂 |
| 人工目录或段落校正 | 新结构版本与旧锚点保留 | 受影响定位投影、窗口与下游综合 |
| 人工 Wiki 修改 | 保存修订、保护区块、检查旧基准冲突 | 相关区块重新编纂，不重做原文分析 |
| Provider/模型改变 | 记录实际模型身份及能力开关 | 对应模型产物/向量代际更新，不清空仍有效旧索引 |

目标调度策略：在线读取与撤回校验优先；关键词小批次独立；整书生成、向量补齐与结构解析由 Mac mini 一个初始重任务名额执行。容量不足时保持排队与断点，不反复记录为分析失败。配置资源上限要包含数据库、检索引擎和原生模型，不能只把各 worker 并发设为 1 就声称总并发为 1。

迁移先在 Mac mini 本地恢复候选数据与现有有效索引，再执行短 schema migration；API 启动不触发全馆分析。先验证旧 URL、登录/私人资料、原 PDF、历史锚点、关键词，再在 Mac mini 重建新版投影。索引 schema 改变可能触发全量重建，[Meilisearch 文档](https://www.meilisearch.com/docs/getting_started/good_practices)对此有说明；采用新代际配置完成后分批写入、校验、切换。旧代际仍可读，回退保留对应代码和索引。

正式切换前冻结正式写入并同步最终数据库增量，核验后再转唯一写入端；不允许新旧两个站点同时写不同数据库。已经发生新端写入后，回退不能只改域名，必须处理新写入的回迁。MCP 仍由其现有部署维护，必要连接配置由后续明确迁移范围处理。
