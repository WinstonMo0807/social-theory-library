# 智能体上传与馆藏更新的MCP接入

日期：2026-11-12。用户要求智能体可上传和维护馆藏，随后要求加入文件上传，并明确校验及限制全部沿网站设计，不增加多余测试。

D：上传接入、辅助程序及部署已完成。B：真实文件上传、续传和入库结果由策展对话试用；本轮没有试传或额外测试。完整记录见[MCP上传交付](MCP_UPLOAD_DELIVERY_20261112.md)。

## 当前流程

新增`stl_prepare_uploads(request_id, files, policy)`和`stl_get_ingestion_status(request_id)`，现共九个工具。上传准备调用原UploadWorkspaceView，二进制分片和状态调用原BatchItemChunkUploadView；文件清单只传name/size，策略透传网站，未提供则使用网站默认值。MCP不新增文件哈希、格式、大小、数量、去重或策略限制，网站原有规则和权限继续生效。

辅助程序`tools/stl_mcp/upload_client.py 文件路径`读取本机选择的文件并直接传输，保存request_id和续传记录。中断后`--resume 请求UUID`从原网站分片继续。文件字节不进入模型上下文，凭据不出现在命令参数或上传回执中。

收到文件后沿网站原任务系统处理；状态工具返回实际接收、派发、处理状态及已生成的Work/Edition ID。动态catalog范围使人或智能体上传的新文献都自动可策展，不再逐书授权。旧策展工具继续读取、查重、取证、保存草稿与断点续做。

## 更新已有馆藏

书目信息、人物、主题、理论关系仍走原MCP草稿与发布流程。本轮上传通道用于新增文件入库；为已有版本补文件、替换当前阅读PDF和选择另一出版版本继续使用网站已有版本/文件工作区及归属流程。不能把本轮新增文件上传说成所有文件更新操作都已新增MCP工具。

原件、历史、笔记、来源和正式发布边界沿网站处理。上传收到、正文处理、策展草稿及公开状态分别返回，上传完成不报成整书策展或发布完成。OCR、索引由原后台队列按网站策略运行，MCP进程不加载模型或运行OCR。
