# 本机 Codex MCP 策展接入与三书实测

日期：2026-11-12，北京时间。状态 D：本机核心流程已接通并完成定向验证；不表示全站验收或从空白完成整书学术策展。

## 已交付

`tools/stl_mcp` 提供七个有类型化输入及结构化输出的工具：检索馆藏、批量上下文、规范实体查重、准确原文取证、准备差异、保存草稿、回执/任务查询。上下文复用原组装函数，但不加载后台队列、知识工作室多套预览；关键词已返回EvidenceSpan时不再重复附带同一批完整页面。

本机 stdio MCP 通过已存在、严格核验主机密钥的 SSH 连接，在原 API 容器中运行固定 Django 命令分派。没有增加远程MCP端口、HTTP服务、Nginx规则、库表、第二套馆藏、NAS依赖或生产源码文件，没有重启业务容器、运行OCR或索引。应用沿原领域服务读取和保存，不用SQL直接改业务完成标志。

独立本机环境位于 `.local/stl-mcp/venv`，固定 MCP Python SDK 2.3.0（MIT），没有改变现有应用虚拟环境。Codex全局配置中新增 `mcp_servers.stl`，仅此服务器采用自动调用模式，服务端仍执行作品范围/账户能力/版本与草稿命令限制。原配置有本机受限备份，未回显或提交其中的值。当前写入范围仅为本次三部作品；其他作品仍可查询，后续按明确任务增加范围。

配置及 journal 位于忽略目录 `.local/stl-mcp`，Windows ACL 限本机账户与SYSTEM。实际运行资料、全文、草稿及回执不入Git。

## 写入边界

- 固定账户与token_version每次重核，模型不能传actor、SQL、Python、shell或任意URL。
- 保存使用原编辑修订服务；即使书目未上架，也不通过人工确认接口直接改正式值。原人工锁、他人草稿及过期版本阻断；集合不能隐式删成员。
- 支持书目/版本及既有通用知识对象草稿、规范人物/出版社/主题/理论传统创建、概念等节点与理论关系的draft创建、原文策展、学者关系和已有观点候选采用。机器来源在修订说明与审计中保留，`human_reviewed=false`，不自动发布。
- 独立文章/版位的新建等仍使用原工作区；其既有内容保留在清单，不将工具尚未覆盖的动作伪称已完成。本期没有加入整书分章抽取或新的生成式模型服务。
- 每项操作独立事务，版本在锁内核验。固定request_id与payload指纹保存在原AuditEvent；回执与业务修改同事务提交。部分失败逐项返回，不能改为整批成功。
- 本机不可变计划、原请求编号和清单持久化到SQLite。断线后查原计划，使用同一plan_id续做。创建新对象后的依赖操作使用创建时的版本回执，不能用临时读取的新版本掩盖并发修改。
- 新原文引用使用活动EvidenceSpan；正文修订、当前文字位置与文件哈希变化后拒绝新保存，不将旧EvidenceSnippet自动提升为新证据。

## 使用与恢复

安装、契约及工具调用顺序见 [本机MCP说明](../../tools/stl_mcp/README.md)。已打开的Codex聊天可能需要重新加载工具或新开聊天后发现新服务器；不能把当前聊天的工具热更新状态写成已观察通过。

代码/配置恢复只移除本机stl注册或恢复其配置，不回滚数据库和后续策展。真实草稿继续由原管理端审阅/修改/发布；不自动删除测试保存的有用引用，也不自动恢复旧数据库覆盖新内容。
