# 稿件版本与增量核验接入

状态：源码已接入，统一功能和视觉验收待核实。唯一视觉依据为最终 PDF 第212页，已实际读取页面图像；沿用第208–215页已接入的上传、报告与问题工作区。

## 实现与数据责任

- 报告和问题详情均接入稿件版本选择、上传新版本、旧报告回看和真实变化摘要。上传默认仅核验变化内容，也可明确选择全量核验。解析未完成时不填充变化数量。
- 每次上传建立独立加密 CitationAudit，保留各版原稿和报告。复用原账户、项目、检查项、范围、Celery和私人OCR，不增加表、迁移或另一套文件库。内部版本基线与关系留在加密payload，不作为报告或导出返回。
- 新旧引文按精确文字、上下文、来源部件及书目对应。重复歧义、内容变化、书目变化、公开修订变化或依据失效均重查；不以模糊相似继承人工结论。人工判断与历史分开保留，OCR再解析优先保留本版有效决定。
- 已复用条目在恢复执行时再检查来源；失效依据加入重查，旧决定留在历史，复用和重查数量同步调整。多条原文匹配中，声明页码判断只使用仍可访问的引用。

## API契约

- `GET /api/reading/citation-audits/{id}/versions/`：本人关联版本，包含`current_id`、`versions`、`truncated`和说明。每版提供实际ID、稿件版本、文件名、状态和时间。最多200条；删除中间版本后关系可能不完整，其他本人记录仍可从任务列表打开。
- `POST`同路径，multipart：`file`、`request_id`、`expected_revision`、`check_changed_only`（默认true），返回202和新记录。原稿须已解析且不处于活动检查中。账户锁、本人最多两项活动任务、文件大小/格式、显式OCR资格均复用既有规则。
- 幂等回放先于过时revision和额度检查。同请求不同输入返回冲突。前端网络重试保留请求标识，409保留所选文件和选项，经本人核对最新报告条件后再提交。
- `data.version_lineage`记录基准与检查模式。`version_comparison.status`为pending或completed；实际比较后提供总数、变化、新增、移除、复用、歧义、书目变化及本轮重查范围。重查范围不是已完成进度。
