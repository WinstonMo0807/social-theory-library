# M27 检索索引备份接入

本项按唯一视觉 PDF 的 M27 存储与备份页实施，复用原 BackupJob、BackupSchedule、维护权限、请求回执、Celery 和归档校验。没有创建第二套检索实例，也没有执行导出、备份、迁移或部署。

## 已接源码

- 可发起独立索引归档，或在完整数据库/原件归档中同时包含索引。四类计划继续出现在原备份任务区域。
- 同一 `MEILISEARCH_URL` 通过官方 `POST /dumps` 导出，保存任务编号后轮询原任务；完成后从配置的共享目录只读复制对应 `.dump`。导出包含该实例全部索引，不默认只保存公开内容。
- 发起前先记录待确认状态。请求超时不自动再次 POST；已知编号的失败备份重试核对同一编号、入队时间、实例地址摘要和服务版本。响应未知不能通过重试按钮重新提交。明确新建备份可能产生另一份导出，页面已说明。
- 定时索引备份失败后暂停计划。管理员核对后明确保存启用计划，才能开始下一次导出；原任务记录和文件保留。
- schema3 归档登记索引 SHA、大小、任务和导出身份、版本、独立快照范围。原 schema1/2 继续读取；带索引的完整原件归档也可以成为增量原件基准。
- 索引校验只证明归档文件完整，不证明导入或查询成功。独立索引归档不显示数据库已校验，不复用数据库演练报告作为索引恢复证据。
- 后端迁移 `distribution0006` 新增范围字段和独立索引约束，依赖0005；两者均未应用。既有数据默认不含索引，账号和归档未清理。

## 挂载与部署准备

`MEILISEARCH_DUMP_ROOT` 默认空，未配置时页面说明原因并禁止发起或启用索引任务。它必须指向当前索引实例完成导出的共享目录，不能指向活动索引数据库。

`compose.index-backup.yaml` 是主 `compose.yaml` 的可选叠加配置，尚未使用。它为已有 Meilisearch 设置 `MEILI_DUMP_DIR=/stl-index-dumps`，将 `${NAS_HOST_ROOT}/backups/search-exports` 映射给 Meilisearch 写入，并给 API、普通 worker 和 beat 同一路径的只读挂载。保留原 compose 文件中的未提交修改，不修改现有活动索引卷。

正式应用前仍须核对实际部署形态、原 Compose 项目、同一目录映射、运行用户读写权限、可用空间和回退。分离式 `compose.nas.yaml` 不可直接套用此全栈叠加文件；必须先确认远端 Meilisearch 和 NAS worker 看到的是同一导出目录。仅设置环境变量不能证明挂载或服务可用。本轮没有连接生产或变更容器。

导出文件和归档都保留，不自动删除。因此索引计划需要同时预留导出及归档空间；现有缓存清理不清理这些备份。运行凭据、模型和应用配置须走原备份/回退安排，不能声称已包含于索引文件。

## 恢复准备与边界

数据库和索引分别生成快照，不保证事务时点一致。准备清单要求新建隔离 Meilisearch 实例，保留源服务版本，不向更旧版本导入，不指向活动索引目录。导出可能包含历史任务和索引配置，隔离环境应阻断生产API、Provider和私有服务访问。导入后核对索引代次、应用映射、撤回状态、读者权限及查询结果，再决定后续切换。

代码仅生成准备清单。未编写自动生产恢复入口，未执行导入、活动索引替换或公网切换。源备份、用户账号、原件、人工锁定内容与私人数据没有改动。

## 证据与尚待验收

静态检查结果见当前进度和恢复记录。延迟验收定义 `api/tests/test_stl4_index_backup_20261025.py` 覆盖导出回执、重试不重发、未知响应、同号异任务、路径越界、源文件保留、独立索引校验范围、计划失败暂停与输入范围。未执行这些测试。

仍需真实挂载/版本/API及导出文件对应核对、NAS资源和任务时限、隔离导入及公开/私人索引映射验收、PDF桌面移动几何对照。工作进程最多轮询900秒，超时保留编号；大索引需要沿原记录继续处理，不能静默另建导出。内网预览尚未启动，本项源码完成不等于全站达到公网切换前条件。
