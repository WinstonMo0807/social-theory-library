# STL 4.0 单主线实施总纲

生效于 2026-10-15。依据本轮用户《Social Theory Library 4.0 全站重构与视觉终稿实施指令》。本目录是持续开发的唯一状态入口；`docs/stl-4.0/` 和其他旧交接保留为历史证据，不再并行维护前后端任务。

## 交付与优先级

在当前工作区完成真实全栈重构，覆盖公共前台、Reader、读者中心、管理端、数据模型、API、检索、队列、文件及最终生产切换。允许重组/替换旧实现，但不能省掉视觉要求的业务行为。一个功能单元同时落实页面、接口、模型、任务、权限和恢复记录。

视觉依据为 `output/pdf/social-theory-library-visual-atlas-20261015-final-r2.pdf`。230 页、209 个有效视图：主页9、探索24、理论16、学者5、主题4、策划6、管理100、读者45。视图不是独立URL数量。旧208图审核目录及 reviewed_candidate/needs_revision 仅作来源追溯。PDF图集外框、编号、批注、制作说明不是网站界面。不得整页贴图、静态mock或虚构生产学术数据。

冲突优先级：本轮用户要求与PDF首页规范 → 最后有效替换图 → 同模块有效页面 → 必要业务补足。最新首页及R01-sub01布局优先旧总览。纸白 `#F7F4EE`、暖灰、炭黑、白色内容层、少量砂金；中文展示标题用衬线、操作用无衬线。禁旧蓝色体系、渐变、重阴影、过度圆角、模板统计卡。桌面、移动、弹层、选中、错误及任务状态均须落实。视觉歧义写 DECISIONS，不因此停工。

## 完整业务范围

| 单元 | 必须实现 |
|---|---|
| 公共发现 | 首页、探索、馆藏检索、观点检索、原文证据、学者、理论/流派、主题、特别策划、作品/版本详情、阅读路径、帮助/关于。搜索、阅读、下载、复制、引用对访客开放。 |
| Reader | 连续滚动、目录、书内搜索、定位、文字选择、批注、引用；保存按登录与所有者权限。复用文件/页码/证据身份。 |
| 私人研究 | 进度、笔记、长期研究会话、证据比较、反证、阅读计划、引文体检、授权笔记、资料导出/删除和隐私。owner隔离，分享由本人显式确认，删除/撤销授权立即失效。 |
| 管理入库 | 批量上传、收件、去重与版本确认、编目、文件处理、OCR、索引、预览、发布、撤回、历史/异常恢复。保存草稿≠预览≠公开发布。 |
| 内容管理 | 学者、理论、概念、主题、策划、共享选书/内容编排；复用馆藏和正式发布关系，机器建议不覆盖人工决定。 |
| 系统 | 同一API/主库/任务/索引/NAS；身份、权限、缓存、运维、审计、备份恢复与资源边界。 |

作品/出版版本/文件/原文证据/知识对象身份清楚。API由视觉数据需求反推，统一稳定类型、错误、分页筛选、状态、版本、鉴权、并发/幂等。按钮必须有真实行为，已有成熟服务优先复用。长任务必须持久化 queued/running/partial/failed/retry/cancelled/succeeded 等真实状态，按业务需要映射，不能只渲染进度。

## 数据重置

保留全部账号ID、密码哈希、角色/权限和登录必需关联。旧馆藏、文件、OCR、索引/向量、知识/策划、统计及私人业务记录属于清理范围。执行必须先核对实际存储位置、外键/队列/缓存、完整备份和恢复能力，支持只读预演与结果核对。不做无边界全库删除。生产不可逆操作需要本轮具体影响与备份核验结果后的最终确认。

已有历史文档记载2026-10-15做过清空；本轮不将记录当作当前生产实测，不重复执行。见 DATA_RESET_PLAN。

## 六项独立验收门槛

- B01：核实 plan_rules.py 输入、排序理由、时间估计、完成项保护与人工调整。不得宣传未实现的预测/个体学习。
- B02：search_memories 的 owner/confirmed/allowed_ids 实际过滤；单条、研究/计划范围、撤销/删除失效与授权持久化。
- B03：体检/解析/OCR的大小、页数、并发、队列、NAS内存、取消和部分报告；不承诺固定耗时或零资源。
- B04：全部私人对象所有者隔离；公开阅读等保持开放。
- B05：真实内容、空态、错误态、部分结果；图中数据不能成为生产种子。
- B06：所有有效视图的真实路由、API、响应式、可访问性、性能与逐图验收。

## 缺失状态与清理

自主补齐断点上传、权限不足、并发冲突、重复判断、服务失联、任务失败/取消、引用缺失、会话过期等状态。优先复用同视觉的抽屉/弹层，不随意增路由。补充项登记索引并注明来源。旧路由/接口/表先追踪调用与数据依赖，再退役，不隐藏异常、不放宽权限、不删除失败证据来制造完成。

## 执行顺序与恢复

先全量功能实施，再统一正式验收。开发期间允许静态阅读、语法/类型检查、安全预演和编写测试；暂不正式E2E、完整功能/视觉回归或部署。全量实施后覆盖API、迁移、账户/权限、上传发布、OCR/索引、检索、Reader、私人功能、任务、空库、性能资源及全部桌面/移动/状态截图。差异必须定位页码/路由并修复复测。

每个业务单元保存Git检查点、契约、索引与PROGRESS。未验证即待核实，旧测试不作为新代码证据。发生中断先读RECOVERY并核对Git/最后修改点。不得覆盖既有未提交工作。生产切换只在全部验收后准备，保留旧站、源码、环境、数据库和镜像恢复入口；最终确认后才执行不可逆数据操作。
