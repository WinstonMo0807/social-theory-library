# 持续增长与业务读取性能优化（2026-11-14）

用户要求继续优化，并明确不限于图片。沿现有 Django、Vinext、PostgreSQL、Redis、Celery、NAS 与 Cloudflare 链路实施；本轮是已有发布授权下的增量，不迁移数据或建立第二套服务。

## 非图片部分

只读剖析发现，首页推荐学者涉及的 6 次知识节点查询占该样本 SQL 时间约 52%（850.82/1622 ms）。原查询对候选知识节点反复匹配作品公开快照中的作者角色。

`public_scholars._knowledge` 先读取最多 513 个匹配的公开修订 ID；不超过 512 时复用有界集合过滤知识节点，避免重复 JSON 作者匹配。超过该数量仍走原完整查询，不截断学者作品或关联。匹配的是公开修订 ID，防止读取期间的新发布替换作者身份。仍沿公开投影及当前版本过滤；人工正式关系、作者/编者区分和撤回规则保持。

`current_recommendations` 增加可选 placement 过滤。首页只读取其实际使用的四个推荐位置，学者/主题页面只读取各自位置；默认调用仍返回原有完整集合。没有引入跨用户缓存、放宽权限或更换搜索服务。

## 内容增长和图片

编辑器准备图片时，沿现有原图、裁切、署名/来源、质量 82 的流程补齐 320/640/1280 三种尺寸。相同版本和尺寸复用已有派生图；公共 GET 只读，不在访问高峰临时转码。没有下调质量参数，没有覆盖原图或旧主图，没有生成无限宽度组合。

旧图只有在冻结元数据与当前焦点能重现同一 group_key 时才补尺寸；焦点已改、旧格式信息缺失则保留旧图，不猜裁切。已发布栏目图计划有 3 张满足该条件。新增派生图通过选中的原主图授权地址访问，再核对同一组的 rendition，继续检查栏目发布、站点及布局使用条件。另一组、错误 ID、未经直接选用的小图地址和撤回主图均不提供访问。

API 为栏目卡片和详情增添可选 cover_media；首页、欢迎页、栏目列表/详情沿真实布局设置 srcset/sizes。浏览器按显示宽度与像素密度选图；旧记录无元数据时保留原 URL。原文件不变，放大查看仍有大尺寸。没有承诺所有屏幕肉眼绝对无差异，也没有将旧书封全部批量改写。

## 物理资源与第三方服务

NAS 5 秒读取样本 pswpin/pswpout 都为 0；I/O 压力约 16%、内存压力约 0.29%，仅用于识别继续测量方向，不足以认定内存/磁盘故障。此前容量样本可用约 4.12 TB，新媒体记录约 162 MB，不含旧馆藏、PDF、OCR 和备份，不能据此推算总增长寿命。

优先在真实并发时量上行占用、路由排队和 NAS 磁盘等待；有持续上行排队再配路由 SQM，有持续换页再扩 RAM，有随机 I/O 瓶颈再考虑 SSD。公开不可变静态文件适合后续对象存储/CDN，但需要先测流量和缓存命中；受保护 PDF 不能改成公共桶或 Cache Everything。已有免费 Cloudflare 能力继续使用；未购买 Argo/Polish/R2、未修改 DNS/安全/隧道配置，未改任务并发或备份时间。
