## 真实业务与保护

- PUT原issue API新增可选request_id/autosave/restore_revision_id；父issue事务锁先查actor+issue+nonce的AuditEvent回执，再CAS。内容指纹不同409。重放只读当前结果，applied_revision_id/is_current_revision区分后来修订；不会重复创建计划书目。
- GET ?request_id查回本账号回执；GET ?revision和history仅同issue，24项分页，真实保存时间/操作者/备注。历史恢复追加草稿，不替换公开修订，回收项不允许隐式复活。
- GET sources复用原材料选择器，加人物/时间线/路径和concept过滤；POST preview只内存解析当前body，复用保存草稿同DTO，不写修订/推荐/发布。
- 只有同区块同类型、已保存的准确来源可以在来源失效时留作草稿；新失效身份拒绝，发布重新检查全部来源。来源不允许编辑、不可用时不保留旧全文展示。
- X-Editor-Owner可选账户防串写校验，前端前后核对cookie身份；账号键重挂载/会话事件清空/原请求生命周期阻断迟到响应。既有客户端不带该header仍按原权限运行。
- sessionStorage只保留可编辑字段和固定请求体，按owner+issue隔离。已保存后删除、退出清除、过期24小时清除。浏览器禁用/写入失败明确提示，未保存输入仍有离页保护。
