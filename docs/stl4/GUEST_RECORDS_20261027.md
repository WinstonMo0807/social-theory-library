# PDF186 访客记录转存

## 需求与最小范围

最终PDF186（R31-main）登录右栏有本机访客记录及主动勾选转存。原auth-page-frame仅静态说明，不读写任何记录；阅读历史仅支持PDF，不能承接公开策划文章。这是VISUAL-73明确开发缺口，沿已有后端草稿完成，不重建账户或阅读服务。

## 已实现

- guest-records.ts仅在未登录状态记录公开PDF当前版本/页码、公开策划文章当前修订与已完成的检索。浏览器版本化存储至多200项，不读取私人笔记、文稿或已登录账户历史。
- 登录页和会话恢复弹层共用转存状态，默认不勾选，显示实际条数。登录完成后按选择调用同账户导入接口；过程中锁住选择。部分未转存或请求不确定时明确提示，可重试或继续原任务，原本机记录保留。
- /reading/guest-records/import/验证登录账户、owner header、公开来源及当前修订；旧来源或停用历史选项不会绕过。幂等回执避免重复；不覆盖账户已有阅读位置。删除后的同一旧回执不复活记录。
- ReadingHistory增量迁移0028支持PDF或策划文章恰好一种来源。读者中心、隐私导出和清理沿同一记录与权限。撤下的文章不泄露正文标题，不生成失效的PDF阅读链接。
- OpenAPI严格生成与前端类型同步。为消除实际阻断契约生成的11条警告，补catalog serializer只读返回类型，并命名原页码操作枚举；没有修改对应业务行为。

## 验证与限制

guest-api-tests.log：初轮9项通过（导入4项+既有历史5项）；追加真实公开文章修订/撤下边界1项通过guest-article-test.log。guest-local-tests.log：2项浏览器本地存储测试通过。Web类型及最终构建guest-web-build-lock.log退出0，严格schema生成guest-contract.log退出0。

这些结果证明指定调用和权限条件，不代替实际账号登录转存验收，也不表示全站视觉通过。内网更新及运行观察以CURRENT_PROGRESS最新记录为准。
