## 已实现

`DiscoverySearchSession` 为 24 小时有效的读者查询记录。查询文字只保存在会话内，不写入 Processing Center 公共任务统计或 Celery 参数；模型仅记录来源标识、来源修订、排序和匹配依据，不复制原文。登录用户必须匹配 owner，匿名用户必须提供创建时返回的随机能力令牌，数据库仅保存其 SHA-256。响应使用 `private, no-store`。

创建后进入现有 Celery 队列。任务只能从 queued 状态原子认领，写回必须同时匹配会话、generation、task_id 与活动状态。取消增加 generation；扩展使用行锁，只允许一次，并将当前访问范围与原范围取交集。迟到任务及重复投递不能重写已取消或新一轮任务。Web 请求只创建或读取任务，不等待模型。

三通道通过共享 discovery projection adapter 召回。标准正文每路预算 100，扩展 300；知识和策展各为 16／40。正文做 RRF、重复与高度重叠切片去重、本地 20／40 候选重排及首六条适度文献分散。扩展最多使用四个真实知识别名分支，各分支总权重低于原问题；不强制支持、反对等立场。重排失败保留融合次序并标明降级。

每通道最多物化 400 个来源引用。扩展只追加未见身份，已有位置不变。签名游标保存原始位置，撤回记录保留为不可见位置，后续页不会因删除前面的命中而重复或跳过另一条结果。每次读取都重新验证来源发布、权限与修订；计数只统计此次仍可见记录。默认三段，前端可读取最多 400 条已显示前缀，以重新验证此前展示过的材料。

上下文接口先验证结果属于此会话，再验证当前来源及其准确 DocumentRevision，只读取同修订的邻近段落和相邻页。异常长段返回真实文字中的连续窗口并说明截断，可跳转 PDF 阅读完整内容。没有可靠坐标时继续标记页级定位。

## API

| 路径（均在 `/api/catalog/`） | 用途 |
|---|---|
| `POST discovery-search/` | `{q, filters}` 创建，返回 202、状态和匿名 access_token |
| `GET discovery-search/{id}/` | 状态与三类结果，`limit` 默认 3，`cursor` 为已签名后续位置 |
| `POST discovery-search/{id}/expand/` | 增加预算并追加结果，不重新排列已找到材料 |
| `POST discovery-search/{id}/cancel/` | 协作取消，已找到的合法材料仍可阅读 |
| `GET discovery-search/{id}/context/?result_id=…` | 当前修订的真实上下文 |

匿名会话后续操作将令牌放入 `X-Discovery-Token` 请求头，不放 URL。登录会话不能凭令牌转给其他账号。GET `viewpoint-search/` 旧接口保留明确的 202 升级说明、`status_url` 与新响应；旧立场分组从默认接口退役，历史人工观点数据未删除。

## 集成边界与运行状态

源码依赖主投影模块的 `discovery_candidates`、`validate_discovery_results` 与 `discovery_coverage`。覆盖计数必须按当前权限实时计算，不返回原缓存中的私人计数。推理客户端使用共享本地服务的 `rerank`，不自行加载模型或外调 API。

Beat 每小时调用 `catalog.tasks.expire_discovery_sessions`（每批最多清理 200 个过期会话）。查询队列默认 `discovery_query`，可用 `DISCOVERY_QUERY_TASK_QUEUE` 配置。全局排队上限默认 12，可用 `DISCOVERY_MAX_QUEUED_QUERIES` 调整。处理中超过 15 分钟或排队超过 30 分钟，后续读取标记失败并保留已找到记录，不让页面无限轮询。

生产通过第三层`compose.discovery.yaml`配置专用查询/索引Worker和`discovery_internal`推理网络；普通Worker只消费`celery`，不能替代专用查询Worker。完整启动、更新和观察命令见[部署说明](DEPLOYMENT.md#308日常运维的统一命令)。索引ProcessingJob与查询会话的超时规则不同：索引运行15分钟或排队1小时才进入失联补偿，避免把串行CPU队列中的正常等待误判为运行失败。
