## 迁移策略

## 源码审计补充

- Reader 原路径为 `distribution.views._public_asset` 及 `active_asset_q`，私有读者记录由 `reading.views.OwnedModelViewSet` 按 user 过滤。保持 URL、规范化 Asset 锚点与页/笔记身份。ReaderShell 当前集成大量本地类型和 hooks，内部拆分不能切换 PDF.js 或权限服务。
- `UnifiedRetrievalPipeline` 只是 Semantic V2 的薄适配器，原样转发 caller 的访问范围。`dependency_engine` 已有明确 projection dependencies，不能另建搜索服务或第二层正式事实。
- `knowledge_publication._activate_completed_revision` 会拒绝较旧事件复活并在事务内切换 revision，原始文件只调整 current 引用而非覆盖；其完整调用与失败条件继续做专项验证。
- KnowledgeNode 已有 merge preview、transaction 与 rollback record，Topic 有 preview/transaction，Person 缺少对应完整工作面。保留真实合并规则，不能按同名自动执行。
- `config.exceptions` 已有全局 DRF exception handler，但手写 Response 错误不会经过它。统一契约需覆盖这两条路径并兼容现有 `error.detail` 客户端。
- `web/.openai/hosting.json` 是 d1/r2 均空的模板残留，没有 project_id。已核对 Sites 的保留既有项目规则。用户明确禁止切换部署平台，本轮不注册或发布新 Sites，不引入 D1 或另一套 auth。仍按 NAS Compose 生产要求执行。
- 真实前端 lint 失败集中在字段助手、封面选择及 KnowledgeWorkspace，涉及 effect 里复位状态和 render 里写 ref。后续需要按上下文隔离状态和取消旧请求，不能关闭 lint 规则。

## 迁移策略明细

CatalogingSession 先新增，旧接口保留 adapter。候选增加 session FK，旧 upload 字段保留兼容；没有可确认所属 Edition 的历史上传保持旧读取，不猜测关联。研究和字段决定只承载过程信息，正式 Work/Edition 不由机器回填。约束变更先审计再应用，任何人工知识冲突只报告。
