# 2.3.1 学科矩阵与知识归位设计

## 设计原则

后台保存文献、学者、学科、理论传统、子学科、主题及其关系。前台页面从这些数据自动汇总。管理员只审核学术判断和少量策展内容，不需要在多个页面重复录入同一本书。

代码中的 `TheorySchool` 名称暂时保留，用于兼容既有数据库、接口和公开链接。它在 2.3.1 中承担理论传统、流派和分支三类理论实体。子学科使用独立的 `Subdiscipline` 模型。主题继续使用 `Topic`，承担按问题意识进入书库的入口。

## PDF 入库后的知识归位

统一复核页分为三栏。

1. 左栏显示 PDF、书目信息页、OCR 状态和证据页。
2. 中栏编辑书目元数据，并选择学科、子学科、理论传统和问题主题。理论关系还可填写文献角色、主次关系、强度和证据。
3. 右栏实时预览发布后会出现的学科页、理论页、子学科页、主题页、学者页、时间轴候选和全文检索入口。

学科、理论和主题都不是发布必填项。无法归类或超出当前三大学科的文献仍可公开阅读、下载和检索。系统建议默认处于待确认状态。管理员修改或确认后的结果优先，后续自动处理不得覆盖。

## 核心实体

### 学科

预置社会学、人类学和民族学。`Discipline` 保存名称、外文名、固定代码、简介、主视觉、排序和公开状态。

新增学科时，管理员在学科管理页创建实体并上传主视觉。知识矩阵接口会自动返回新学科。前台学科卡片、筛选项、理论时间轴和图谱入口随公开关系自动形成，无需新写页面。固定代码和 slug 使将来的数据导入与链接保持稳定。

### 理论传统

理论实体保存标准名称、外文名称、别名、层级、形成时期、概述、核心问题和主视觉。它与学科、子学科、其他理论、文献、主题和学者通过关系表关联。

理论关系包含影响、继承、分化、批评、综合和相邻。只有人工确认的关系进入公开图谱。上位传统和下位分支也使用独立关系，并保留审核状态和证据。

### 子学科

子学科保存所属学科、上级子学科、研究对象、核心问题、形成时期、研究方向、常用方法和代表性议题。它与理论传统通过关系表连接，理论传统不会被当作子学科的父级分类。

### 问题主题

主题保存问题陈述、核心问题、研究维度、常用方法、形成背景和关键概念。主题页自动聚合相关理论、子学科、学者、馆藏、证据摘录和阅读路径。它不替代理论传统或子学科。

## 关系证据

文献与理论关系支持奠基文献、理论发展、入门综述、经验应用、方法使用、理论批评、理论史研究和局部提及。关系还保存主次、强度、置信度、证据 PDF、页码、书页标签、证据片段、审核人和审核时间。

时间轴事件单独保存。出版年份不会自动变成理论史事件。只有附有证据并由管理员确认的事件进入公开时间轴。

## 推荐与策展

全站读者在同一三天周期内看到同一组推荐。系统为精选馆藏、理论传统、学者、问题主题、随机推荐和理论页馆藏分别生成快照。管理员可随时更新、置顶、排序或排除，手动更新会重新开始三天周期。

四类文献都可进入推荐。图书优先使用确认的封面。期刊论文、学位论文和研究报告使用首个有效 PDF 页面图例。管理员可为任一文献上传替代图，也可恢复系统生成结果。

## 图片资产

后台提供以下入口。

- 学科、子学科、理论传统和主题的主视觉
- 学者肖像
- 图书封面候选确认
- 每篇馆藏的推荐图替换或重新生成

图片存入共享公开媒体目录。容器重建不会清空。前台没有图片时继续使用现有黑白占位设计。

## 新增学科的标准步骤

1. 在后台新增学科，填写固定代码、名称、介绍、排序和主视觉。
2. 按需新增子学科。
3. 在理论或主题编辑页建立与新学科的关系。
4. 在 PDF 复核页确认文献和学者的学科关系。
5. 公开学科和已确认关系。

完成后，知识矩阵、筛选器、学科详情和聚合数量会自动更新。新学科不需要增加数据库表、复制前端页面或改写推荐服务。
