# 后台管理员使用指南

更新日期：2026-08-19
适用版本：2.8.0 源码与本地预览；生产仍为 2.7.1

## 1. 使用边界

- [SOURCE] 本指南只描述当前代码中已经存在的页面、权限和操作。
- [LIVE] 2.8 尚未部署。下列页面已通过本地真实浏览器，生产仍需在每次发布后用真实角色重新核对，不能用本地截图代替公网权限验证。
- [SOURCE] 上传、元数据复核、发布、OCR、页码和语义索引使用同一套馆藏记录。保存元数据不会自动发布。
- [SOURCE] 原始 PDF、人工锁定字段、已确认关系、读者笔记和数据卷不得因日常操作被覆盖或删除。

## 2. 角色与权限

| 角色 | 当前可执行的主要操作 | 不能执行的操作 |
| --- | --- | --- |
| 管理员 `admin` | 查看全部后台页；上传、复核、重试、替换；最终发布、下架、移除入库记录；系统健康、语义索引、设置和用户管理 | 无额外业务限制，仍受技术 blocker 和服务端校验约束 |
| 编辑 `editor` | 创建上传批次、上传文件、导入标准书目、复核元数据、处理实体候选、刷新外部候选、重试处理；维护现有权限允许的馆藏和知识内容 | 不能最终发布、下架或移除入库记录；管理员专用页面不在导航中显示 |
| 审核者 `reviewer` | 查看上架记录和处理状态；执行当前 API 允许的元数据与知识审核 | 不能上传、重试、替换、发布、下架或移除入库记录；管理员专用页面不显示 |
| 读者 `reader` | 使用公开站点和本人阅读中心 | 不能进入后台 |

后台前端会按 capability 隐藏无权限入口，服务端仍会再次校验。角色只用于组织一组 capability，不要只依赖按钮是否显示或直接比较角色名称。

## 4. 推荐上架流程

上传完成并建立 Work / Edition 后，进入 `/admin/intake/<itemId>`。正常操作不再跳转 Scholar、Theory、Reading Path 或 Publication 页面。左侧 step rail 可回到任何步骤，当前步骤展开，已完成步骤折叠，下一步骤显示提示。保存并继续会重新读取后端 workflow；存在 blocker 时留在原步骤并定位问题。

固定顺序为文件与识别、作品、书目与出版、责任者、社科分类、理论与主题、阅读文件、策展、发布。策展可以选择“暂不策展并继续”，不构成发布 blocker。发布可选择处理下一项或留在当前项；留在当前项会进入 `/admin/library/works/<workId>`，继续使用同一 Editor Engine。

候选和 evidence 通过右侧 Inspector 核对。正式 Person、Discipline、Theory、Topic、KnowledgeNode 与解释性关系仍需人工决定；置信度不会自动变成 canonical knowledge。Canonical 字段保存前显示未保存计数，Ctrl/Cmd+S 可保存，离开未保存工作会提示。

### 4.1 创建上传批次

进入“上架 / 批量上传”。先设置本批处理方式，再拖入 PDF。

| 选项 | 默认值 | 使用建议 |
| --- | --- | --- |
| 批次标签 | 空 | 用日期、来源或专题标识批次，便于后续筛选 |
| 访问范围 | 公开访问 | 只决定文件初始访问范围，不等于公开发布 |
| OCR 策略 | 自动检测 | 通常保留。系统先检查原生文字，只处理扫描页 |
| 重复策略 | 发现重复时人工确认 | 通常保留，避免把同一作品的不同版本误判为重复 |
| 外部元数据补充 | 开启 | 来源不可用时仍能继续本地识别 |
| AI 候选建议 | 关闭 | 只有模型已配置且允许发送摘录时再按批次开启 |

三种访问范围的含义如下。

- 公开访问允许访客读取已发布文件。
- 登录读者要求已登录读者。
- 受限访问只允许工作人员通过受保护入口读取。

三种 OCR 策略的含义如下。

- 自动检测只把扫描页排入 OCR。
- 强制 OCR 会处理全部页面，消耗更多 NAS 资源。
- 跳过 OCR 不处理扫描页。扫描件可以发布和查看图像，但复制、全文检索和语义能力会受限。

三种重复策略的真实行为如下。

- 人工确认把完全重复文件送到复核状态。
- 阻止完全重复文件把该上传项标为失败。
- 允许继续入库会关联已有 Asset 和 Edition，不复制第二份相同原文件。

### 4.2 上传与恢复

2.7.1 公网上传把 PDF 直接发送到临时 R2 staging，文件不会先经过应用服务器。页面显示实际上传字节、最近约 5 秒当前速率、累计有效平均速率和按近期速度计算的预计剩余时间。

操作要求：

1. 站内切换到其他页面不会停止当前上传。重新返回上传页可继续看到进度。
2. 浏览器完整刷新或关闭后无法继续持有本地 File，这是浏览器安全限制。上传页仍显示服务端会话；重新选择文件名、大小和修改时间一致的 PDF 后继续未完成 part。
3. 约 5 秒没有新字节时显示“连接等待中”，百分比不增长。单个 part 约 18 秒没有进度时只重试该 part，最多三次。
4. R2 multipart 完成后页面显示“上传完成，正在入库”。这时不要重复选择文件。Ingestion Worker 正在把完整 PDF 流式写入正式 NAS 并进入原处理流程。
5. 若显示“PDF 已安全上传，入库失败，可重试”，PDF 仍在 R2 staging。点击重新入库，不需要再次上传。
6. 入库完成后应用会主动删除 staging object。清理失败不会撤销书籍，后台会继续重试。

页面会逐项显示文件大小、页数、文本类型、检测到的 OCR 页数、计划 OCR 页数、重复结果和当前处理阶段。预检信息尚未生成时显示等待状态。

### 4.3 查看批次结果

每个 PDF 独立处理。一个文件失败不会把整批已成功文件回滚。

- 有 Edition 的条目可进入“复核识别候选”。
- 有管理员发布权限的条目可进入“发布确认”。
- 失败条目进入 Processing Center 查看错误和重试。
- 完全重复且选择允许继续时，会复用已有馆藏文件。

## 5. 元数据复核

进入“上架 / 元数据复核”或从批次结果打开单项记录。

### 5.1 页面结构

当前复核页包含以下区域。

- 最终馆藏元数据表单。
- 识别候选、来源、评分因素和证据。
- 实体消歧提示。
- PDF 预览、规范文本、文本来源、页码校对和处理历史。
- 封面或推荐图候选。
- 发布影响预览。

### 5.2 候选处理

候选是建议，不是正式值。

1. 查看候选值、规范值、来源、页码、证据和冲突。
2. 点击“填入表单”只会把值放入编辑区，不会立刻接受候选。
3. 检查版本层级。出版社、出版地、印刷者和发行者不要混填。
4. 保存复核内容后，匹配当前表单值的候选才会记录为接受。
5. 接受后的字段默认锁定。后续识别不得覆盖人工锁定值。
6. 明确错误的候选可拒绝，误拒后可恢复为待审。

同名人物不会仅凭姓名自动合并。实体候选卡提供确认关联、创建草稿、保留未解析名称和拒绝四类决定。确认关联人物时必须明确确认身份；创建的人物或知识节点保持草稿，不会直接生成公开学者页或公开知识页。每次决定写入决定日志与操作审计。普通审核者不能改写这些馆藏实体。

### 5.3 导入标准书目

复核页可上传一条 RIS、BibTeX、CSL-JSON 或 sidecar JSON 记录。文件必须使用 UTF-8，最大 512 KiB。一个文件只能包含一条书目记录。

导入后每个字段以待审候选展示，并保留来源文件、原始字段和来源记录。它不会直接修改作品、版本或发布状态。相同文件重复导入会复用来源记录并保留既有人工接受、拒绝和锁定决定。当前没有引入 YAML 解析依赖，YAML 文件会提示改用 sidecar JSON。

### 5.4 保存与发布

未发布馆藏点击“保存复核内容”只会保存元数据、锁和决定日志。页面会提示进入发布台。

已经发布的馆藏点击“保存公开元数据”会更新其元数据和相关索引任务，但不会替换原始 PDF，也不会改变发布状态。

复核进度不足 100% 不会剥夺管理员发布权。它会成为发布 warning。

### 5.5 移除复核记录

未发布记录可以由管理员选择“移除复核记录”。确认框只要求确认，不要求输入文件名。该操作把记录从处理中心和复核队列隐藏，保留 NAS 原始文件、已生成资产和审计记录。

## 6. 发布台

进入“发布 / 发布台”。该页面是最终公开决定入口。

### 6.1 发布前检查

发布台把问题分为三组。

| 类型 | 当前含义 | 是否阻止管理员发布 |
| --- | --- | --- |
| Technical blockers | 原始 PDF 不可读、公开阅读锚点不存在或无效、部署要求的云副本缺失 | 是 |
| Warnings | 元数据不完整、复核未满、OCR 未完成或失败、页码待校对、语义或全文索引未就绪 | 否，但必须再次确认 |
| Background tasks | 发布后应继续运行的 OCR、页码、语义或全文索引任务 | 否 |

管理员发布步骤：

1. 在左侧选择待处理馆藏。
2. 查看 PDF 预览、书目信息和公开影响。
3. 点击“重新检查”。
4. 如果有 blocker，先处理文件或存储问题。
5. 如果只有 warning，点击发布后阅读提示，再点击“确认发布”。
6. 查看发布结果中的索引 warning 和已安排任务。

公开发布由管理员明确操作。OCR、页码或语义任务失败不会自动撤销已发布状态。公开索引刷新失败时，API 会记录审计事件并返回 warning，管理员应到处理中心继续排查。

### 6.2 下架与重新发布

管理员点击“下架”后只需确认，可选填原因，不需要输入文件名。

下架会改变 publication state，并尝试移除全文和语义查询文档。数据库、原始 PDF、OCR 派生物、页码、索引历史和稳定标识保留。索引清理失败会返回 warning，但下架状态仍然保留。

重新发布仍使用同一 Edition 和稳定 URL。发布时间模型保留首次发布时间和最近发布时间，编辑旧元数据不会把首次发布时间重置。

## 7. Processing Center

进入“上架 / Processing Center”。

页面先按任务类型筛选，再按状态筛选。

任务类型包括：

- OCR
- 页码识别
- 语义索引
- 缩略图
- 缓存刷新

状态包括：

- pending
- running
- succeeded
- failed
- canceled

每项任务显示馆藏、状态、进度、engine、尝试次数、起止时间、耗时和最近错误。failed 任务可以重试，pending 任务可以取消等待。历史错误不会自动消失，也不应仅凭旧错误判断当前模型仍然不可用。

下方“上传流程记录”保留每个 UploadItem 的阶段、停滞时间、错误、复核入口和发布台入口。管理员移除记录时使用简单确认框，物理文件和审计记录保留。

## 8. OCR 管理

OCR 的运行设置位于系统设置和 System Health。处理结果在 Processing Center 查看。

### 8.1 选择策略

- 日常入库优先使用自动检测。
- 已知扫描质量复杂且必须复制全文时，可选择强制 OCR。
- 仅在明确接受没有文字层时使用跳过 OCR。

### 8.2 识别失败

1. 先确认原始 PDF 在 Reader 中仍可翻页和查看。
2. 查看 OCR job 的 engine、attempt、settings version 和 last error。
3. 检查 System Health 中 PaddleOCR 的 configured、available 和最近错误。
4. 配置问题修复后，在 Processing Center 人工重试。
5. 不要替换或覆盖 ORIGINAL_PDF。

Remote OCR 未配置时应显示 not configured。若 mode 为 NAS 优先，远程 URL、模型和 API key 三项缺一，远程回退不可用，但本地 PaddleOCR 仍可独立工作。

## 9. 引用页码校对

元数据复核页的“页码校对”用于区分 PDF 页序和书上印刷页码。

例如 PDF 第 48 页的书页顶部印为第 32 页，应保存：

```text
file_page_index = 48
printed_page_label = 32
```

Reader 仍用 PDF 第 48 页定位，页面显示和引用生成使用第 32 页。

操作步骤：

1. 打开页码校对标签。
2. 点击“重新分析”，按人工映射、PDF PageLabels、OCR 页眉页脚、连续序列和文件页序的优先级生成候选。
3. 在目标 PDF 页输入印刷页码并保存锚点。
4. 前言和正文编号不同的书，分别建立多个 segment。
5. 选择阿拉伯数字、大小写罗马数字、自定义标签或无页码。
6. 分页检查低置信度和编号重启位置。
7. 点击“确认当前映射”。

自动分析只生成候选。书中无页码、重复页码、附录重编号和复杂混排仍需人工校对。

## 10. Semantic Index

进入“搜索与模型 / Semantic Index”。该页面目前提供运行配置、任务状态、失败重试和真实查询检查。

“混合检索权重”表示关键词和向量结果的融合比例，不是质量分数。模型不可用时页面应显示当前不可生效，查询自动使用关键词降级。

管理员排查顺序：

1. 查看当前 provider、model、revision、offline mode 和本地模型健康。
2. 区分旧 Hugging Face 网络错误与当前 health。历史 failed 记录不会因模型修复而删除。
3. 用查询检查器比较关键词结果、语义结果、融合结果、分数、过滤条件和耗时。
4. 只重试失败项目，避免无依据地全量重建。
5. 更换模型时创建候选 IndexRevision，不覆盖 active 索引。
6. 等候选版本 ready，核对文档数和模型配置后人工切换。
7. 保留旧 revision，发现退化时切回。

Semantic Index 页面已经接入馆内检索评估。管理员可以建立评估集、添加中文或英文查询与人工相关性判断，先做预检，再交给 Celery 异步计算 Recall@20、nDCG@10、MRR、零结果率和 p50/p95 延迟。页面显示进度与历史运行。评估不会下载模型，也不会切换活动索引。

## 11. System Status

System Status 为受 capability 保护的只读页。当前检查 Database、migration、storage、Worker、队列、Beat、QueryLexicon、Semantic Index、embedding、AI、Web Provider 和 BackupJob 等组件。旧 System Health route 只保留为兼容诊断入口。

每个组件应区分：

- configured
- available
- last successful check
- last error

可选 Remote OCR 未配置时不应算作全站故障。健康检查结果为 configured 只表示配置形状正确，不表示一次真实 OCR 或 embedding 已成功。

端到端自检应使用小型测试文件，并在结果中逐步显示 storage read、PDF parse、OCR、text extraction、embedding、Meilisearch write、search 和 page retrieval。生产运行前需确认自检使用临时记录，不污染正式馆藏。

## 12. 危险操作

馆藏、子学科、理论流派和其他实体的移除应使用确认对话框，不要求管理员再次输入名称。确认框应同时显示影响范围。

当前入库记录删除采用软移除并保留文件。其他实体页面已有 archive、restore 和 delete 生命周期入口，但永久删除仍可能受外键依赖保护。执行前应查看依赖预览。完整的统一依赖预览和通用回滚界面尚未覆盖所有对象。

不要执行以下操作：

- 删除数据库卷、媒体卷或模型卷。
- 用 OCR 文件覆盖原始 PDF。
- 删除当前生产 Meilisearch 索引后再重建。
- 在没有备份时反向迁移新表。
- 为让页面显示正常而手工修改生产数据库状态字符串。
- 接受来源不明、版本不匹配或只有同名命中的人物候选。

## 13. 读者侧相关行为

当前源码中的读者中心会显示最近五项继续阅读记录。系统不会为了只显示五项而删除更早的阅读历史。

读者收藏一本书时，后端会同时确保该书存在 ReadingProgress。这样收藏栏能保留继续阅读入口。取消收藏不会自动删除历史进度。

Reader 选择文字后出现的操作顺序为：复制、高亮、划线、笔记、书签。在线阅读、下载、复制、搜索和引用对访客开放；个人高亮、笔记、书签、收藏和进度需要登录。
