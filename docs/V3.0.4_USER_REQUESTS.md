## 最初三十五节要求

1. 正式馆藏为唯一可信知识源；保存草稿与发布分离；普通后台隐藏机器复杂度，保留原视觉语言。
2. 修改前完整审计模型、候选采用、证据、词典、OCR、索引、预览、策展与发布流程，形成五类处置清单。
3. 用统一字段助手封装现有馆内、OCR、权威、联网和检索能力，不机械新建重复服务。
4. 取消普通全局候选中心，候选归属字段，后端去重聚合，默认最多三项。
5. 普通界面不显示候选分数，改为采用建议、待确认、冲突及依据。
6. 作者、译者、出版社、版本年份、封面、简介与分类分别采用适合该字段的策略。
7. 上架顺序仅是导航，任意顺序编辑，状态按真实字段动态计算。
8. 建立字段依赖，未确认候选可失效，人工确认值只提示复查，不自动覆盖。
9. 采用候选必须在事务内写真实草稿字段、关系、决定、审计和依赖状态，任一步失败整体失败。
10. 普通界面明确作者、译者、主编、编者、校注、摄影和其他贡献者，不使用含混称谓。
11. 编目内搜索、新建并关联学者、主题、理论和出版社，不要求离开作品后再返回搜索。
12. 新实体是当前编目草稿，重复预检，通过完整性检查后随作品发布包生效。
13. 学者、主题、理论、学科、Knowledge Studio 和阅读路径同样采用统一字段助手。
14. 区分临时证据、正式馆藏、可重建派生智能三层；派生结果不能反向作为正式事实。
15. QueryLexicon 只取正式名称与确认别名/规范关系，支持变更、合并、撤回和删除。
16. RAG 只使用合格正式正文和确认编辑材料，保留来源、版本及页码；未确认 AI 内容不得进入。
17. 观点检索仅服务已发布、允许检索且质量合格的正文，准备计算不能提前生效。
18. 向书库提问维持馆内边界，不偷偷混入互联网资料。
19. 拒绝反馈可用于排序和评测，不进入正式事实、词典或 RAG，不做未经评估的在线训练。
20. 正式发布产生明确知识事件，通过事务 outbox 和幂等任务更新各消费者。
21. 正式内容有 revision，新版本准备期间旧稳定版本继续服务，失败有重试入口。
22. 按字段影响增量更新，纯封面不重做 OCR/embedding，元数据修改不重跑全库。
23. 扫描 PDF 可先发布；正文等待合格 OCR，明确 metadata ready 与 fulltext ready。
24. 上架队列只展示待审核、冲突、不完整、可发布、处理中和异常，不显示技术任务数量。
25. 紧凑预览与无 Admin 侧栏的完整预览共用真实公开组件，并按容器宽度响应。
26. 图书、论文、整期期刊采用不同模板；整期期刊支持目录与论文列表。
27. 发布前检查真实字段、关系、文件、冲突和新增实体，不要求依次访问步骤；选填项允许不适用。
28. 日常后台使用馆藏与审核业务语言；内部标识和技术细节留在诊断。
29. 安全迁移旧数据，审计 accepted 但字段为空、重复身份、索引缺失或草稿泄漏，不无规则批量破坏馆藏。
30. 原要求 A–J 完整场景涵盖采用、乱序编辑、草稿隔离、正式发布、新学者、拒绝、更新失败保护、只换封面、主题合并和撤回。
31. 后台可预取，须防抖、取消、缓存及增量失效；外部失败不能阻止手工编目。
32. 普通状态使用草稿已保存、可以发布、已发布、智能处理中、已进入检索和异常，技术堆栈另置。
33. 禁止只改卡片/前端、保留错误状态机、候选直接入知识、用分数代替依据、全量重建、强制顺序或删除可靠能力。
34. 正式馆藏增长后优先利用馆内人物、别名、理论、主题与版本关系，互联网只是补充。
35. 交付审计、五类清单、架构、迁移、后端、工作台、策展、预览、三类隔离、事件、审计工具、测试资产、升级说明和限制。不得只报告页面完成。
