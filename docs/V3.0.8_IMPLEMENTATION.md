## 使用与数据边界

`/explore/opinions` 沿用书库暖灰、黑白编辑型布局，分别展示原文、知识和策展。默认三段原文；查看更多读取已物化的后续材料；扩大研究追加预算与真实别名分支，不重新排列已有结果。原文详情恢复同一 DocumentRevision 的连续上下文，保留 PDF 页码和 Reader 链接。没有可靠字符坐标时明确按页定位，不展示学术真假、首创或立场评分。

历史 `viewpoint-search` API 返回升级说明及异步状态链接，已有人工观点和旧索引继续保留。原文检索、Reader、知识页、推荐期和阅读策划沿用既有模型和入口。管理员无需再填第二套图谱。

索引来源只读当前已发布的馆藏修订、知识与公开策展。阅读策划的 `editorial_note` 在 3.0.7 是私人备注，因而不采纳开发包将其作为公开文本的建议；使用 `recommendation_reason`、导言和学习目标。查询会话只保存结果身份与排序，每次翻页及上下文访问重新核对当前权限、来源修订与原文切片。访问范围、卡片和计数同时过滤。

## 索引和任务

复用 `SemanticIndexVersion` 和 `ProcessingJob`，增加 discovery 分类。旧语义索引管理器只读取 semantic 分类，避免误激活或覆盖。`DiscoveryDocument` 和 `DiscoverySourceState` 是可重建派生投影，不替代原始 PDF、页、人工确认或文件版本。迁移 0060—0062 和 ingestion 0018 均为增量 schema，没有删除旧数据或改写原文。0062 保留索引分类的数据库默认值，旧3.0.7 ORM写入兼容已在隔离PostgreSQL实际事务验证并回滚。

发布、OCR/页文字变化、策展和知识更新在事务提交后唤醒专用索引队列，定期协调器补偿 bulk update 和队列中断。小批次分块按实际 tokenizer 控制长度，规范化文本只用于搜索，展示切片保持原文。Meilisearch 使用固定本地 E5 向量，真正收到写入成功后才记录完成。新 generation 准备完成且数量核对一致后切换，旧 generation 继续保留。重复任务、旧修订和断点恢复均通过任务身份与版本核对。

处理中心分别显示阅读、文字/OCR、关键词、向量和既有知识关系投影，实际模型准备与实际推理完成分开显示。Owner 可以建立新索引版本，既有重试权限可以重试失败索引；没有扩大权限。查询任务走 `discovery_query`，索引走 `discovery_index`，各一并发；现有上传/OCR继续使用 ingestion。

## 模型、重建与回退

参见 [本地模型说明](DISCOVERY_LOCAL_INFERENCE.md) 和 [查询接口](V3.0.8_QUERY_SESSIONS.md)。模型固定修订、文件 SHA、384 维、前缀、masked mean 与 L2 身份均记录。使用通用 FP32 ONNX，实际目标是已核对无 AVX/AVX2 的 N5105；兼容性仍须以实际 NAS 推理为证。

在完成模型与本轮迁移准备的服务环境里，可通过处理中心建立版本，或使用 `python manage.py discovery_index build --keep-ready`。`status` 查看版本，`reconcile` 补偿中断，`activate --generation UUID` 显式激活已核对 ready 或保留 retired 版本。命令不自动删除旧索引、模型或原件。完整派生重建与增量进度保持可见，24 小时为日常更新观察目标，不伪造完成保证。

应用回退使用本轮发布前保存的实际 3.0.7 镜像、环境和 Compose，先停止本轮新增查询/索引 worker 与推理服务，再以新代码退役 discovery 的building、ready及active代次并取消未完成派生任务，避免旧管理器和迟到消息误用它们；保留所有派生行、增量 schema、新资料与旧semantic活动索引。`discovery_index deactivate --generation UUID`提供有界单代次退役。恢复 Edge 后核对 HTTP、Worker 与公开 Reader。数据库恢复和反向迁移不属于应用回退。
