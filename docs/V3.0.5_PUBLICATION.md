# 发布命令与恢复

开发分支的发布准备、验证、激活、撤回和恢复入口集中在 `catalog/services/publication_commands.py`。旧 ingestion publish/withdraw 保留为兼容适配，调用同一命令层。仍复用正式 revision、outbox 和消费者，不增加数据库或队列。

准备发布是只读操作。它比较保存的编辑字段与活动公开快照，区分新增、移除、修改和未变化，分别提供必须处理、警告和后台处理。指纹包含真实字段、确认信息和公开基线；实际提交时再次检查。工作台原“确认发布更新”入口也先展示差异。

Model.save 与 QuerySet.update 禁止改写已有 CatalogPublicationRevision 的内容、文档和作品归属。状态、投递就绪和错误诊断可更新。数据库已有每 Edition 一个 active 的部分唯一约束，跨 Edition 的指针由公开查询与命令验证共同拒绝；原始 SQL 的跨表约束仍需 PostgreSQL 阶段评估，不能将 Python guard 写成数据库 trigger。

回滚只接受属于当前 Edition 且 activated_at 存在的合法旧修订，必须检查历史文件仍可读。采用旧快照创建序号更高的恢复发布，原修订不修改，迟到旧事件不能重新成为活动版本。恢复完成前旧活动指针继续服务。撤回作品不能借回滚隐式重新公开。

此操作恢复公开版本，保留之后的人工作品编辑值。二者有差异时显示待发布修改，下一次发布仍需显式核对，不自动覆盖人工新数据。当前尚未证明真实 PostgreSQL 并发、恢复时真实索引与 Reader 文件旅程，不能据本地受控消费者测试部署生产。

## 本轮验证

发布安全、原发布、编辑修订和不可变内容组 38 passed。旧两项测试改为验证真实维护发布 HTTP 单事件和已有扁平 changed_fields，定向 2 passed。旧 Reader 夹具现于 revision 创建时设置文档信息，不关闭不可变检查。TypeScript、lint、schema 生成和 migration drift 通过。最新浏览器差异/历史组仍按 CURRENT_PROGRESS 的精确记录交接。
