# 3.0.5 人物查重与合并影响预览

## 当前交付范围

2026-09-11 已实现只读查重服务、影响预览 API 和生成契约。没有人物合并执行接口，没有持久回滚接口，也尚未接入前端操作页。响应固定返回 `merge_execution_available=false`，不能把这一步记为完整 Person Merge。

| API | 权限 | 行为 |
| --- | --- | --- |
| `GET /api/catalog/admin/people/{person_id}/duplicates/` | 既有后台访问能力 | 返回馆内名称或标识符匹配候选 |
| `GET /api/catalog/admin/people/{person_id}/merge-preview/?target_person={uuid}` | 既有 `CanMergeAuthority`，仅 System Owner | 读取来源、保留人物与相关引用，显示差异和复核问题 |

查重只使用规范名称、已核验名称变体和同字段标识符。同名不是同人证明，原始混合别名不单独作为匹配依据。支持旧数据中的整型标识符，但不去掉标识符中有意义的前导零。不使用外部 Provider 或 AI 推断身份，也不写入候选、事件或索引。

标识符字段名固定作为JSON键精确匹配，不允许被解释成Django查询操作符。对应边界测试先红后绿，最终人物/权限/契约/词典同步52项通过。OpenAPI与TypeScript由真实serializer生成并通过漂移检查，运行命令及环境限制见 `V3.0.5_VERIFICATION.md`。

## 已核对引用

| 所属对象 | 模型与字段 |
| --- | --- |
| Person | Person.merged_into、PersonNameVariant.person、ScholarProfile.person、Contribution.person |
| Person 的知识关系 | PersonKnowledgeRelation、PersonSubdisciplineRelation、PersonDisciplineRelation、PersonTopicRelation、PersonNodeRelation 的 person |
| ScholarProfile | TheoryTimelineEvent.scholar、TimelineEventRelation.scholar、CuratedClaim.scholar、RecommendationItem.scholar、RecommendationOverride.scholar |

当前为9类 Person 引用和5类 ScholarProfile 引用。服务以实际 Django 关系元数据核对显式清单，出现未知 FK 会拒绝预览。

预览还列出相关书目、公开修订标识、相关对象的编辑草稿和活动词典词条。公开修订只读取标识与状态，不返回历史快照中的正文。不会读取读者私人笔记，也不会重写旧文件、公开快照或未审核候选。

每组最多显示500行。超限会设置 `complete_reference_listing=false` 并报告范围不完整。这个字段仅表示本次声明的引用列表是否完整，不证明所有通用候选 JSON、历史文本或 URL 都已扫描。

`lexicon_entries` 使用 `QueryLexiconState.active_generation`，只返回活动版本的来源与目标词条、语言、来源类型、信任等级及公开/后台检索资格。来源、目标计数均不包含退役版本。未初始化或状态不一致时 `available=false`，预览范围也标记为不完整。预览不会调用初始化、同步或重建词典，也不会修复活动指针。词条资格变化或活动版本切换会改变预览指纹。

`fingerprint` 标识本次显示的事实，人物或引用变化时应重新预览。它不是合并授权，也不能直接替代未来执行器的加锁和完整校验。

## 后续执行与回滚必须补齐

1. 先确定两个 ScholarProfile 同时存在时的内容、唯一关系、公开 URL 和历史推荐处理方式。不得静默覆盖人工内容。
2. 对 Contribution 与各类关系的唯一约束冲突给出明确处理，保留原审核状态、来源和证据。已确认与已拒绝相冲突时不得自动择一。
3. 核对 PublicationBundle、CatalogFieldDecision、FieldLock、编辑草稿及通用候选引用。当前预览没有穷尽这些通用 JSON，执行器不得直接进行全局字符串替换。
4. 在事务内按固定顺序锁住来源、目标和受影响记录，重新计算完整影响范围。保留来源 Person，使用既有 merged_into 规则，不删除原件或旧公开修订。
5. 更新通过既有持久发布事件处理，书目旧正式版本保留到必要处理完成。候选名称不能因身份合并而未经复核成为正式别名。
6. 保存可审计的操作记录和回滚所需状态。失败应整笔回滚；持久回滚必须检测后续人工变更，不能覆盖合并后新增的资料或私人阅读数据。
7. 前端使用已验证的账号能力与按人物对隔离的请求状态。只有完整预览、冲突处理和人工确认后才启用执行。

本地 SQLite 回归不能证明 PostgreSQL 并发锁、真实索引或生产恢复可用。对应验收仍待执行。
