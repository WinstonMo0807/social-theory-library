# 3.0.5 人物查重与合并影响预览

## 当前交付范围

2026-09-11 已实现查重、影响预览及第一版非冲突合并、操作记录和持久回滚API，尚未接入前端操作页。原只读服务仍不写数据；指定目标的Owner预览会进一步评估执行条件，仅在完整且无阻断时返回 `merge_execution_available=true`。此版本不处理双档案取舍或重复唯一关系，不能称为任意人物都可自动合并。

| API | 权限 | 行为 |
| --- | --- | --- |
| `GET /api/catalog/admin/people/{person_id}/duplicates/` | 既有后台访问能力 | 返回馆内名称或标识符匹配候选 |
| `GET /api/catalog/admin/people/{person_id}/merge-preview/?target_person={uuid}` | 既有 `CanMergeAuthority`，仅 System Owner | 读取来源、保留人物与相关引用，显示差异和复核问题 |
| `POST /api/catalog/admin/people/{person_id}/merge/` | 同上 | 校验确认、指纹、幂等标识后执行非冲突合并 |
| `GET /api/catalog/admin/people/merge-records/{record_id}/` | 同上 | 返回操作状态、关联发布事件和当前回滚条件 |
| `POST /api/catalog/admin/people/merge-records/{record_id}/rollback/` | 同上 | 校验人工确认和当前状态，恢复本次移动的引用 |

查重只使用规范名称、已核验名称变体和同字段标识符。同名不是同人证明，原始混合别名不单独作为匹配依据。支持旧数据中的整型标识符，但不去掉标识符中有意义的前导零。不使用外部 Provider 或 AI 推断身份，也不写入候选、事件或索引。

标识符字段名固定作为JSON键精确匹配，不允许被解释成Django查询操作符。对应边界测试先红后绿，最终人物/权限/契约/词典同步52项通过。OpenAPI与TypeScript由真实serializer生成并通过漂移检查，运行命令及环境限制见 `V3.0.5_VERIFICATION.md`。

## 已核对引用

| 所属对象 | 模型与字段 |
| --- | --- |
| Person | Person.merged_into、PersonNameVariant.person、ScholarProfile.person、Contribution.person |
| Person 的知识关系 | PersonKnowledgeRelation、PersonSubdisciplineRelation、PersonDisciplineRelation、PersonTopicRelation、PersonNodeRelation 的 person |
| ScholarProfile | TheoryTimelineEvent.scholar、TimelineEventRelation.scholar、CuratedClaim.scholar、RecommendationItem.scholar、RecommendationOverride.scholar |

当前为9类 Person 业务引用、2类新增的合并审计引用和5类 ScholarProfile 引用。审计记录始终保留原来源与目标，不随下一次身份合并改写。服务以实际 Django 关系元数据核对显式清单，出现未知 FK 会拒绝预览。

预览还列出相关书目、公开修订标识、相关对象的编辑草稿和活动词典词条。公开修订只读取标识与状态，不返回历史快照中的正文。不会读取读者私人笔记，也不会重写旧文件、公开快照或未审核候选。

每组最多显示500行。超限会设置 `complete_reference_listing=false` 并报告范围不完整。这个字段仅表示本次声明的引用列表是否完整，不证明所有通用候选 JSON、历史文本或 URL 都已扫描。

`lexicon_entries` 使用 `QueryLexiconState.active_generation`，只返回活动版本的来源与目标词条、语言、来源类型、信任等级及公开/后台检索资格。来源、目标计数均不包含退役版本。未初始化或状态不一致时 `available=false`，预览范围也标记为不完整。预览不会调用初始化、同步或重建词典，也不会修复活动指针。词条资格变化或活动版本切换会改变预览指纹。

只读指纹标识本次显示的事实。执行预览另纳入编辑上下文与规范版本，人物或引用变化时应重新预览。合并还必须提交 `confirmed=true` 和有效 `idempotency_key`，执行器会加锁并重新计算指纹。只读指纹不能直接作为执行授权。

## 第一版执行范围

双方均须已核验，身份字段没有冲突，至多一份ScholarProfile，没有重复唯一关系及未完成的相关编辑上下文。两份档案、重复关系、排队/运行中的研究、待审核候选、开放发布包和相关编辑草稿均阻止执行。不是通过删除其中一条记录来解决冲突。

来源人物保留并标为merged，指向保留人物。保留人物的基础资料不自动覆盖或填充，来源简介、图片和标识符仍留在来源人物及不可变操作快照中。执行预览明确展示这项策略。无冲突引用保持原记录ID，只改变身份FK；未核验名称仍未核验。唯一学者档案可转移其person FK，档案ID、slug、内容和下游引用保留。

作者/译者人工字段中的明确Person ID随已确认身份改变，原审核者、状态、证据、锁定理由不变，并追加字段日志。其他含来源ID的人工字段会阻断，不对文本做全局替换。已接受或结束的历史候选保留原记录，待处理候选须先处理。通用JSON采用有界筛查，超限不执行。

合并使用事务和固定顺序的人物锁，沿用词典generation锁及请求幂等锁。实体和受影响已发布书目沿用持久发布事件，不直接写搜索索引。书目继续服务旧活动修订，直到新处理完成。后续回滚用新的修订恢复书目，不改写旧快照。

## 操作记录与回滚

0051新增PersonMergeRecord，保存来源、目标、原始快照、移动字段、事件ID和回滚指纹。Model/QuerySet禁止改写内容与删除，批量upsert也不能绕过保护。记录不保存或修改读者私人笔记。

回滚需重新读取操作详情并提交其中的指纹。人物、关联、锁定值或编辑状态存在后续变更时拒绝覆盖。只忽略模型维护的行级时间戳，不忽略业务JSON内部同名日期键。新阅读笔记不属于回滚范围，不阻断回滚，也不会被删除或改写。合并与回滚任一步失败，整笔数据库事务回滚。

仍在准备的本次合并修订会在回滚时失效；新的恢复发布完成后，迟到旧事件不得重新成为活动版本。重复提交同一合并或已完成回滚返回原操作状态，不再重复迁移。
