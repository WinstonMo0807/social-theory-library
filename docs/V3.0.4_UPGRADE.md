# Social Theory Library 3.0.4 升级说明

核对日期为 2026-09-05。当前为待执行升级说明，3.0.4 尚未完成生产迁移或公网切换。用户已授权部署，并要求不再追加功能测试；授权、源码落盘和实际部署不能混写。最新构建、提交及执行记录见 [CURRENT_PROGRESS.md](../CURRENT_PROGRESS.md)。

本说明只覆盖 3.0.3 到 3.0.4 的数据与应用边界。环境、备份入口、镜像和回退操作继续以 [DEPLOYMENT.md](DEPLOYMENT.md) 为准。逐项实现及未验证内容见 [需求矩阵](V3.0.4_REQUIREMENTS_MATRIX.md)，升级前真实数据情况见 [生产数据库只读审计](V3.0.4_DATABASE_AUDIT.md)。

## 当前已经实现的变化

3.0.4 将编目草稿、正式馆藏修订和派生智能内容分开。管理员手工保存或采用建议不会触发正式知识发布。已发布 Edition 或共享已发布 Work 的修改先保存为 EditorialRevision，正式确认后才建立 CatalogPublicationRevision 和知识发布事件。

字段助手复用现有馆内实体、OCR、结构化书目、FieldPolicy、Evidence、实体解析、权威来源和联网服务。作者、译者、出版社、本版年份、简介、主题和理论使用字段级建议；相同值先在后端合并，再展示少量可读结果。封面继续使用专门的 PDF/版本匹配服务，并遵守相同草稿边界。

工作台已经支持任意顺序保存。完成度来自真实字段决定，不来自打开过哪些步骤或候选 accepted 数量。人工确认的值不会被后台依赖失效删除。新实体可以在当前编目中创建并关联，先留在发布包，正式发布时检查完整性并共同发布。

图书、论文和整期期刊使用不同书目字段。整期期刊目录可增删、排序、填写页码并关联馆内论文；目录随修订发布，草稿论文不会产生公开链接。已保存的题名、ISBN 和作者上下文稳定后，工作台防抖预取后续书目建议与当前版本封面。短缓存、取消与失效仅控制临时结果，不写入正式字段。

作品的核心观点、主要批评和回应使用同一字段助手，复用既有 DerivedClaim 审核接口。采用结果只写独立 CuratedClaim 草稿，不触发正式投影，也不会把已有正式观点直接改为草稿。正式发布后，公开作品观点还须属于活动馆藏快照的 curated_claim_ids；新修订准备期间不会提前出现。

公开详情、全文、语义、观点和 Ask 使用活动馆藏修订。metadata ready 与 fulltext ready 分开，扫描 PDF 可以先开放阅读，合格正文在后续异步处理完成后进入智能检索。新正文处理失败时保留上一稳定正文。

## 数据库迁移

0040 另为历史草稿中已有明确人工确认关系的草稿学者、主题和理论建立待发布包，必要时补最小草稿学者资料。它不公开实体、不改变未确认关系，不根据机器候选状态回填。正式发布会再次检查当前关联，移除的对象不会发布。今后的普通字段确认保存同样登记当前管理员确认的草稿实体。

工作台的智能内容状态条可对失败记录请求重新处理。操作要求相应发布权限，复用已有事件和修订，保留已完成消费者和原活动内容。旧错误与手动重试进入审计，不清空失败历史。已经被较新修订替代的内容不能重新激活。

| 迁移 | 作用 | 数据保护边界 |
| --- | --- | --- |
| `catalog.0040_v304_cataloging_intelligence` | 字段决定、发布包、馆藏修订、知识事件、消费者投递，以及 Edition 的活动修订和就绪状态；正式馆藏初始化快照。 | 不据 accepted 自动接受事实；保留正式字段、原始文件和现有关系。只有已有质量评估满足门槛，历史正文才设为 fulltext ready。 |
| `catalog.0041_v304_asset_text_revisions` | Asset 增加 text_revision；将历史 hash/kind 唯一性限定于 text_revision=0，为新正文解释添加 edition/kind/text_revision 唯一性。 | 历史 Asset/文件保持不变。新 OCR 解释使用独立规范 Asset、Page、Passage、Chunk，原 PDF 字节共享不覆盖，旧对象仍可引用。 |
| `catalog.0042_v304_journal_issue_articles` | 新增 JournalIssueArticle，保存整期目录题名、作者展示、页码、顺序和可选馆内论文关系；同一期与同一论文不能重复关联。 | 仅新增关系表，不猜测历史目录，不修改既有论文或原文件。公开目录使用正式快照，关联草稿论文不开放链接。 |

0041 不仅增加字段，还调整唯一约束。部署前必须在备份恢复副本中执行完整迁移序列，不能把“additive”理解为任意旧代码都能安全回退。尤其当新 text_revision 已出现，同一 kind/sha256 可以有多个正文解释，旧代码的单对象查询不再足够。

OCR staging 保留人工页码映射。OCR 任务重试复用同一 staging Asset。正式内容事件携带捕获的 Asset、DocumentRevision 和变更字段，处理成功后再切换当前规范阅读文件及对应 OCR PDF。

## 三类索引的版本化

| 派生内容 | 新文档标识 | 活动指针与公开过滤 |
| --- | --- | --- |
| 全文 passages | 馆藏索引修订与 passage_id 组合 | `fulltext_index_revision_id`，同时受正式全文资格约束。 |
| Semantic passages | 馆藏语义索引修订与 chunk_id 组合 | `semantic_index_revision_id` 与活动阅读 Asset，V1/V2 共用资格过滤。 |
| Claim Index | 馆藏观点索引修订与 claim_id 组合 | `claim_index_revision_id`，并检查活动 DocumentRevision。 |

0040 的历史快照使用显式 legacy 指针。新修订写入自己的命名空间，不删除上一稳定命名空间。所有必要消费者成功后才切换正式活动指针。较早任务即使迟到完成，也不能覆盖较新的正式请求或恢复已撤回馆藏。

同一正文只改作者、年份或分类等检索元数据时，语义消费者取回旧向量并以禁止重新生成的方式写入新命名空间，不重新配置 embedder。若旧向量不完整，则更新失败并保留旧版本，不偷偷改成整本重新 embedding。只换封面不触发正文消费者。

尚未激活的正式修订被后续发布替代时，后续事件继承未完成的变更范围和捕获正文。这样，作者更新尚在处理期间发布封面，也不会遗漏作者索引更新。同 Work 的其他已发布 Edition 对共享字段各自取得更新事件。

## 旧索引字段准备

切换应用之前，需要让当前三个索引认识新的发布过滤字段。新增命令只读取指定的全文索引、唯一活动 Semantic UID 和现有 Claim Index，不创建或清空索引，不改文档、向量或 embedder 配置。

先查看计划，将输出保存在受控部署记录中。

```bash
python manage.py prepare_v304_search_indexes
```

确认目标、备份及计划后执行。

```bash
python manage.py prepare_v304_search_indexes --apply --wait-seconds 45
```

该命令仅追加缺少的 filterable/displayed 属性，保留原设置。缺失的索引列为 missing_no_change，不自动建立；多个活动 SemanticIndexVersion 会阻断执行。重复执行不重复追加字段。

Meilisearch 添加过滤属性时可能异步处理既有过滤结构，但这不是清空索引、重传全文或重新计算 embedding。命令会先输出修改前字段、修改计划和任务编号，单次等待上限为 60 秒。超时不取消已经提交的任务，先检查其状态，不能据此删除活动索引。

迁移窗口中，旧全文/语义索引若尚未支持新属性，只允许在全部仍为 legacy 的活动正式对象范围内有界兼容。现代修订不能绕过版本过滤。Claim Index 出错继续使用现有正式数据库检索回退。兼容行为不能替代上述升级准备。

## 升级前实际数据基线

2026-09-05 已通过生产只读事务及真实搜索文档盘点确认 9 Work、9 Edition，其中 6 本已发布、3 本草稿。全文和语义索引未发现草稿且 is_public=true 的记录。这一结论属于旧生产版本，不等于新版隔离验收。

已确认的问题包括已发布作品没有 approved 作者关系、正文质量为 0 或低于新门槛、历史草稿人物仍待发布、用户暂停 OCR、以及 accepted 但无审核人/时间的旧候选。详见 [数据库报告](V3.0.4_DATABASE_AUDIT.md)。这些问题不应通过自动接受人物、猜测角色或覆盖人工元数据修复。

旧词典必须按照新的正式来源 registry 受控重建。不能因为旧 QueryLexicon 条目 public_active 就把来源当成已确认；同时保留旧 generation 与索引回退入口。真实数据中的歧义项只生成审核事项。

## 执行顺序与检查边界

1. 使用现有 BackupJob 生成完整备份，保存数据库 dump、源码、环境和镜像回退记录，并核对校验值。
2. 在独立 PostgreSQL 16 恢复同一备份，执行 migration plan 和 0040、0041、0042 迁移演练。原对象 ID、ORIGINAL 摘要、页码身份及馆藏数量需要前后对照。
3. 保存当前活动 Semantic UID、QueryLexicon generation、文件集合和任务状态。用户已暂停的 OCR 不得擅自恢复。等待正常写任务结束后，暂停会领取新任务的相关 Worker/Beat。
4. 构建同一源码版本的 API、Worker、Ingestion Worker 和 Web，应用已经演练的 Django migration。
5. 运行索引字段准备命令及迁移后的只读一致性审计，再滚动切换应用。容器地址变化后刷新 Edge。
6. 按部署规范记录 readiness、版本、数据库迁移状态、原有 Reader/PDF Range 和公开访问结果。用户要求不新增功能测试，不能把未执行的 A–J 场景写为通过。

可在候选镜像或恢复副本运行以下计划与审计命令。生产完整数据审计须在 schema 已对齐后执行。输出目录由部署记录选择，已有文件不会被覆盖。

```bash
python manage.py migrate --plan
python manage.py audit_v304_catalog_consistency --database-read-only --schema-only --output /path/to/deploy-record/v304-schema-audit.json
python manage.py audit_v304_catalog_consistency --database-read-only --limit 100 --output /path/to/deploy-record/v304-catalog-audit.json
```

schema 不匹配时，报告必须明确 data_checks_executed=false，不能把缺表造成的空结果误报为无异常。生产迁移、索引属性准备和最终检查的执行结果应另行追加到部署记录。

## 回退

不得运行 docker compose down -v，不得删除 ORIGINAL、数据库、备份、模型、当前索引或历史修订，也不得用旧数据库覆盖正在服务的新 schema。

应用层回退保留新增 schema 和索引命名空间。0040、0041、0042 反向迁移会丢失修订或目录关系，或者使旧唯一约束无法恢复，不应作为常规回退操作。新 text_revision 已创建后，只有经过兼容核对、能够处理多正文解释的旧/修复镜像才可接管。不能默认升级前镜像对新数据安全。

派生处理失败时优先保留活动指针，暂停受影响任务并通过现有事件或修订恢复入口处理。不要通过删除失败记录、清空索引或重新识别整库掩盖错误。必要的正式活动修订回退应使用有审计的受控服务，不直接修改生产表。

## 已知限制与验收状态

- 新工作台、主要策展页面及发布隔离已实现。理论审核页的原始置信度控件已移除，作品三类观点与 Knowledge Studio 普通字段均复用共享助手；原技术汇总和诊断操作保留到 `/admin/system-health/knowledge`。对象深链接、草稿值和实体/版本重试已接入，实际界面行为未做最终验收。
- 三类资源的差异模板、整期目录、900ms 防抖预取、前后台短缓存、取消和上下文失效已经实现，实际编辑与请求行为未做最终功能验收。预取复用已有证据和真实封面服务，不自动启动大型联网研究。
- 外部来源、真实 OCR、远程模型、异步时序及大规模检索质量未由当前源码检查证明。
- 历史作者角色、异名实体及缺少审核凭据的 accepted 候选需要人工决策。只读审计不会自动修复馆藏。
- 旧 TheorySchool、Concept、WorkKnowledgeRelation 和候选表继续保留为兼容或诊断能力，不因后台简化而删除。
- AI 辅助简介须经管理员确认并正式发布，保留 AI-assisted 来源，不得变成原始正文或模型历史回答的再学习材料。
- 最新工作树未追加功能测试；较早单元和定向回归只证明当时版本。A–J 完整验收和实际公网切换目前均未完成。
