## 当前已经实现的变化

3.0.4 将编目草稿、正式馆藏修订和派生智能内容分开。管理员手工保存或采用建议不会触发正式知识发布。已发布 Edition 或共享已发布 Work 的修改先保存为 EditorialRevision，正式确认后才建立 CatalogPublicationRevision 和知识发布事件。

字段助手复用现有馆内实体、OCR、结构化书目、FieldPolicy、Evidence、实体解析、权威来源和联网服务。作者、译者、出版社、本版年份、简介、主题和理论使用字段级建议；相同值先在后端合并，再展示少量可读结果。封面继续使用专门的 PDF/版本匹配服务，并遵守相同草稿边界。

显式重新查找已接既有异步调度，预取只读取准备好的证据和短缓存，不自动发起大型联网研究。外部权限不足或来源失败时保留馆内查找和手工编辑。馆内人物候选的拒绝也只记反馈，不进入正式知识。完全没有 UploadItem 的手工 Work，其外部 Person 候选持久化仍受原服务限制。

工作台已经支持任意顺序保存。完成度来自真实字段决定，不来自打开过哪些步骤或候选 accepted 数量。人工确认的值不会被后台依赖失效删除。新实体可以在当前编目中创建并关联，先留在发布包，正式发布时检查完整性并共同发布。

图书、论文和整期期刊使用不同书目字段。整期期刊目录可增删、排序、填写页码并关联馆内论文；目录随修订发布，草稿论文不会产生公开链接。已保存的题名、ISBN 和作者上下文稳定后，工作台防抖预取后续书目建议与当前版本封面。短缓存、取消与失效仅控制临时结果，不写入正式字段。

作品的核心观点、主要批评和回应使用同一字段助手，复用既有 DerivedClaim 审核接口。采用结果只写独立 CuratedClaim 草稿，不触发正式投影，也不会把已有正式观点直接改为草稿。正式发布后，公开作品观点还须属于活动馆藏快照的 curated_claim_ids；新修订准备期间不会提前出现。

公开详情、全文、语义、观点和 Ask 使用活动馆藏修订。metadata ready 与 fulltext ready 分开，扫描 PDF 可以先开放阅读，合格正文在后续异步处理完成后进入智能检索。新正文处理失败时保留上一稳定正文。

## 数据库迁移

下表三项迁移已在生产应用，不是尚待执行的清单。后续恢复和回退仍需遵守各项数据边界。

0040 另为历史草稿中已有明确人工确认关系的草稿学者、主题和理论建立待发布包，必要时补最小草稿学者资料。它不公开实体、不改变未确认关系，不根据机器候选状态回填。正式发布会再次检查当前关联，移除的对象不会发布。今后的普通字段确认保存同样登记当前管理员确认的草稿实体。

工作台的智能内容状态条可对失败记录请求重新处理。操作要求相应发布权限，复用已有事件和修订，保留已完成消费者和原活动内容。旧错误与手动重试进入审计，不清空失败历史。已经被较新修订替代的内容不能重新激活。

## 三类索引的版本化

| 派生内容 | 新文档标识 | 活动指针与公开过滤 |
| --- | --- | --- |
| 全文 passages | 馆藏索引修订与 passage_id 组合 | `fulltext_index_revision_id`，同时受正式全文资格约束。 |
| Semantic passages | 馆藏语义索引修订与 chunk_id 组合 | `semantic_index_revision_id` 与活动阅读 Asset，V1/V2 共用资格过滤。 |
| Claim Index | 馆藏观点索引修订与 claim_id 组合 | `claim_index_revision_id`，并检查活动 DocumentRevision。 |

0040 的历史快照使用显式 legacy 指针。新修订写入自己的命名空间，不删除上一稳定命名空间。所有必要消费者成功后才切换正式活动指针。较早任务即使迟到完成，也不能覆盖较新的正式请求或恢复已撤回馆藏。

同一正文只改作者、年份或分类等检索元数据时，语义消费者取回旧向量并以禁止重新生成的方式写入新命名空间，不重新配置 embedder。若旧向量不完整，则更新失败并保留旧版本，不偷偷改成整本重新 embedding。只换封面不触发正文消费者。

尚未激活的正式修订被后续发布替代时，后续事件继承未完成的变更范围和捕获正文。这样，作者更新尚在处理期间发布封面，也不会遗漏作者索引更新。同 Work 的其他已发布 Edition 对共享字段各自取得更新事件。

## 旧索引字段准备

以下保留切换前的操作方式，实际执行记录见部署记录，不要求现在重复运行。切换应用前需让当前三个索引认识新的发布过滤字段。新增命令只读取指定的全文索引、唯一活动 Semantic UID 和现有 Claim Index，不创建或清空索引，不改文档、向量或 embedder 配置。

先查看计划，将输出保存在受控部署记录中。

```bash
python manage.py prepare_v304_search_indexes
```

确认目标、备份及计划后执行。

```bash
python manage.py prepare_v304_search_indexes --apply --wait-seconds 45
```

该命令仅追加缺少的 filterable/displayed 属性，保留原设置。缺失的索引列为 missing_no_change，不自动建立；多个活动 SemanticIndexVersion 会阻断执行。重复执行不重复追加字段。

Meilisearch 添加过滤属性时可能异步处理既有过滤结构，但这不是清空索引、重传全文或重新计算 embedding。命令会先输出修改前字段、修改计划和任务编号，单次等待上限为 60 秒。超时不取消已经提交的任务，先检查其状态，不能据此删除活动索引。

迁移窗口中，旧全文/语义索引若尚未支持新属性，只允许在全部仍为 legacy 的活动正式对象范围内有界兼容。现代修订不能绕过版本过滤。Claim Index 出错继续使用现有正式数据库检索回退。兼容行为不能替代上述升级准备。

## 回退

不得运行 docker compose down -v，不得删除 ORIGINAL、数据库、备份、模型、当前索引或历史修订，也不得用旧数据库覆盖正在服务的新 schema。

应用层回退保留新增 schema 和索引命名空间。0040、0041、0042 反向迁移会丢失修订或目录关系，或者使旧唯一约束无法恢复，不应作为常规回退操作。新 text_revision 已创建后，只有经过兼容核对、能够处理多正文解释的旧/修复镜像才可接管。不能默认升级前镜像对新数据安全。

派生处理失败时优先保留活动指针，暂停受影响任务并通过现有事件或修订恢复入口处理。不要通过删除失败记录、清空索引或重新识别整库掩盖错误。必要的正式活动修订回退应使用有审计的受控服务，不直接修改生产表。
